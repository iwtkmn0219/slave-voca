- 대상: `feat/ui-redesign`, 테스트 135개 통과, typecheck·lint·build 통과(DB를 읽는 화면은 모두 ◐)

## Step 3. 키보드 흐름

| 확인 | 결과 |
|---|---|
| 검토: 첫 행 클릭 → 다섯째 행 Shift+클릭 | 다섯 행이 해제된다. 요약은 "해제한 25개"이다. BERT에는 사전에 없어서 처음부터 해제된 단어가 20개 있어 20 + 5다. 계획서의 "5개"는 기본 해제가 없는 경우의 값이다. "해제함" 필터 행 수도 25이다. |

| 검토: 체크박스 포커스 위 Space | 한 번만 바뀐다(이중 처리 없음). |

## Step 4. Designer 검수

목업과 거의 일치한다는 판정을 받았다. 지적 6건 중 5건을 반영했다(`e58a37a`). 6번은 데이터 문제라 수정하지 않았다.

1. 읽어야 하는 글자에서 faint(3.6:1)를 빼고 muted(4.9:1)로 바꿨다. 대상은 검토 해제 행의 단어와 문장, "발음기호 없음" 2곳, 복습 앞면 안내문, 업로드 placeholder다. 제안서 3.1·7·8장의 faint 용도도 "비활성·장식 전용, 글자에는 쓰지 않음"으로 고쳤다.
2. 포커스 행에서 "이미 학습 중" 배지가 행 바탕에 묻히던 것을 surface 칩으로 바꿨다.
3. 발음 버튼, 필터 칩, "보이는 행 모두 선택/해제"가 마우스 클릭으로 포커스를 가져가지 않게 했다. 브라우저 확인 결과: 칩을 누른 뒤 Space를 누르면 포커스 행이 체크된다. 발음 버튼을 누른 뒤 Space를 누르면 뒷면이 열리고 발음은 1번만 나온다. Tab 포커스는 그대로다.
4. 뜻 실패 점선을 정수 픽셀(2px)로 바꿔 행마다 색이 다르게 보이던 것을 고쳤다.
5. 검토 화면 단어 열을 300px에서 240px로 줄였다. line-clamp는 넣지 않았다(강조 단어가 3번째 줄에 있는 행이 있음).
6. (수정 없음) bert가 두 개 보이는 것은 확인용 DB 사본의 데이터 때문이다.

## 남은 것 (기록)

- 검토 행 밀도: BERT처럼 문장이 길면 1280×900에서 약 9행이 보인다. 근본 해결은 추출 단계에서 단어 주변을 더 짧게 자르는 것이고, 기능 변경이라 PM 판단 사항이다(Designer 의견).
- CodeReviewer Minor: 완료 화면에서 "다시 확인" 링크에 포커스가 있을 때 Enter를 누르면 링크 이동과 홈 이동이 함께 실행된다.
- CodeReviewer Minor: 응답해도 상단 메뉴의 오늘 남은 수 배지는 화면을 옮기거나 새로고침해야 바뀐다(복습 화면에는 자체 남은 수 표시가 있다).
- CodeReviewer Minor: 다크 토큰이 `prefers-color-scheme`용과 `data-theme`용으로 두 번 정의되어 있어, 값을 바꿀 때 두 곳을 같이 고쳐야 한다.

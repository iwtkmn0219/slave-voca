# M6-1: 로그인·가입 승인 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 비공개 베타를 위해 Google 로그인과 가입 승인을 넣는다.
- 로그인하지 않은 사람은 로그인 화면으로 간다.
- 처음 가입한 사람은 관리자가 승인할 때까지 승인 대기 화면만 본다.
- 관리자(`ADMIN_EMAILS`)는 `/admin`에서 승인·사용 중지·다시 허용을 한다.
- 모든 화면·Server Action·API가 로그인과 승인을 확인한다.

**Architecture:**
- **인증:** Better Auth 1.7.7(Drizzle·SQLite 어댑터, 표 이름 복수형)
- **로그인 확인 계층:** `src/server/auth/current-user.ts`의 `requireUser()`가 앱 화면 데이터 구성 요소와 Server Action의 입구다.
- **1차 확인:** `src/proxy.ts`가 세션 쿠키가 없는 요청을 화면을 그리기 전에 로그인으로 보낸다.
- **화면 구조:** 화면을 라우트 그룹 `(app)`(상단 바 있음)과 `(auth)`(없음)로 나눈다. 주소는 그대로다.
- 데이터는 아직 사용자별로 나누지 않는다(M6-2).

**Tech Stack:** 기존 스택 + `better-auth` 1.7.7(정확한 버전 고정)

## Review Focus

1. 승인되지 않은 계정(대기·사용 중지·로그인 안 함)이 어떤 Server Action이나 API로도 데이터를 읽거나 바꾸지 못하는지. 모든 `"use server"` 함수의 첫 줄과 `/api/usage-meaning`의 401을 본다.

3. `next` 열린 리디렉션: `//evil.example`, `/\evil.example`, `https://…`, 인증 화면·API 경로가 모두 홈으로 바뀌는지(`safeNextPath`). Google `callbackURL`에도 같은 값만 들어가는지.

5. 사용 중지하면 세션이 모두 지워지고 다음 요청부터 막히는지. 로그아웃·로그인 뒤 브라우저에 이전 사용자의 화면이 남지 않는지(전체 다시 열기).

```ts
import { eq } from 'drizzle-orm';
import { beforeEach, describe, expect, it } from 'vitest';
import { createDb, type Db } from '@/server/db/client';
import { users } from '@/server/db/schema';
import { createAuth } from '@/server/auth/auth';

// 실제 Better Auth를 메모리 DB에 붙여 가입 규칙을 확인한다. Google 대신 개발 전용 로그인(이메일)을 쓴다.
const env = {
  BETTER_AUTH_URL: 'http://localhost:3300',
  BETTER_AUTH_SECRET: 'test-secret-test-secret-test-secret-32',
  ADMIN_EMAILS: 'owner@example.com',
  AUTH_DEV_LOGIN: '1',
};

let db: Db;
beforeEach(() => {
  db = createDb(':memory:');
});

const signUp = (auth: ReturnType<typeof createAuth>, email: string, extra: Record<string, unknown> = {}) =>
  auth.api.signUpEmail({ body: { email, password: 'password-1234', name: email.split('@')[0], ...extra } });

describe('createAuth', () => {
  it('makes admin emails approved admins and everyone else pending users', async () => {
    const auth = createAuth(db, env);
    await signUp(auth, 'Owner@Example.com');
    await signUp(auth, 'friend@example.com');
    const rows = db.select({ email: users.email, status: users.status, role: users.role }).from(users).all();
    expect(rows).toEqual(
      expect.arrayContaining([
        { email: 'owner@example.com', status: 'approved', role: 'admin' },
        { email: 'friend@example.com', status: 'pending', role: 'user' },
      ]),
    );
  });

  it('ignores status and role sent by the client', async () => {
    const auth = createAuth(db, env);
    await signUp(auth, 'sneaky@example.com', { status: 'approved', role: 'admin' });
    const row = db.select().from(users).where(eq(users.email, 'sneaky@example.com')).get();
    expect(row && { status: row.status, role: row.role }).toEqual({ status: 'pending', role: 'user' });
  });

  it('turns off email sign-up when the dev login is off', async () => {
    const auth = createAuth(db, { ...env, AUTH_DEV_LOGIN: undefined });
    await expect(signUp(auth, 'friend@example.com')).rejects.toThrow();
    expect(db.select().from(users).all()).toEqual([]);
  });
});
```

```ts
import { sql } from 'drizzle-orm';
import { index, integer, sqliteTable, text } from 'drizzle-orm/sqlite-core';

// Better Auth(1.7)가 쓰는 표. 모양은 Better Auth의 SQLite 스키마를 따르고, 표 이름은 다른 표처럼
// 복수형이다(drizzleAdapter usePlural). status·role은 가입 승인을 위해 더한 열이다(M6-1 설계 2장).

export const USER_STATUSES = ['pending', 'approved', 'blocked'] as const;
export type UserStatus = (typeof USER_STATUSES)[number];
export const USER_ROLES = ['user', 'admin'] as const;
export type UserRole = (typeof USER_ROLES)[number];

const now = sql`(cast(unixepoch('subsecond') * 1000 as integer))`;
const createdAt = () => integer('created_at', { mode: 'timestamp_ms' }).default(now).notNull();
const updatedAt = () =>
  integer('updated_at', { mode: 'timestamp_ms' })
    .default(now)
    .$onUpdate(() => new Date())
    .notNull();

export const users = sqliteTable('users', {
  id: text('id').primaryKey(),
  name: text('name').notNull(),
  email: text('email').notNull().unique(),
  emailVerified: integer('email_verified', { mode: 'boolean' }).default(false).notNull(),
  image: text('image'),
  status: text('status', { enum: USER_STATUSES }).notNull().default('pending'),
  role: text('role', { enum: USER_ROLES }).notNull().default('user'),
  createdAt: createdAt(),
  updatedAt: updatedAt(),
});

export const sessions = sqliteTable(
  'sessions',
  {
    id: text('id').primaryKey(),
    expiresAt: integer('expires_at', { mode: 'timestamp_ms' }).notNull(),
    token: text('token').notNull().unique(),
    createdAt: createdAt(),
    updatedAt: updatedAt(),
    ipAddress: text('ip_address'),
    userAgent: text('user_agent'),
    userId: text('user_id')
      .notNull()
      .references(() => users.id, { onDelete: 'cascade' }),
  },
  (table) => [index('sessions_user_id_idx').on(table.userId)],
);

export const accounts = sqliteTable(
  'accounts',
  {
    id: text('id').primaryKey(),
    accountId: text('account_id').notNull(),
    providerId: text('provider_id').notNull(),
    userId: text('user_id')
      .notNull()
      .references(() => users.id, { onDelete: 'cascade' }),
    accessToken: text('access_token'),
    refreshToken: text('refresh_token'),
    idToken: text('id_token'),
    accessTokenExpiresAt: integer('access_token_expires_at', { mode: 'timestamp_ms' }),
    refreshTokenExpiresAt: integer('refresh_token_expires_at', { mode: 'timestamp_ms' }),
    scope: text('scope'),
    password: text('password'),
    createdAt: createdAt(),
    updatedAt: updatedAt(),
  },
  (table) => [index('accounts_user_id_idx').on(table.userId)],
);

export const verifications = sqliteTable(
  'verifications',
  {
    id: text('id').primaryKey(),
    identifier: text('identifier').notNull(),
    value: text('value').notNull(),
    expiresAt: integer('expires_at', { mode: 'timestamp_ms' }).notNull(),
    createdAt: createdAt(),
    updatedAt: updatedAt(),
  },
  (table) => [index('verifications_identifier_idx').on(table.identifier)],
);

export type UserRow = typeof users.$inferSelect;
```

```ts
import type { UserRole, UserStatus } from '@/server/db/auth-schema';

// 가입 승인 규칙(M6-1 설계 2장). 서버·테스트가 함께 쓰는 순수 함수만 둔다.

export interface AccessUser {
  status: UserStatus;
  role: UserRole;
}

// ADMIN_EMAILS: 쉼표로 나눈 이메일 목록. 대소문자와 앞뒤 공백은 무시한다.
export function parseAdminEmails(value: string | undefined): ReadonlySet<string> {
  return new Set(
    (value ?? '')
      .split(',')
      .map((e) => e.trim().toLowerCase())
      .filter(Boolean),
  );
}

// 새 계정의 처음 상태. 관리자 이메일은 바로 승인된 관리자, 나머지는 승인 대기다.
export function initialAccess(email: string, admins: ReadonlySet<string>): AccessUser {
  return admins.has(email.trim().toLowerCase())
    ? { status: 'approved', role: 'admin' }
    : { status: 'pending', role: 'user' };
}

// 화면을 열 수 없을 때 보낼 곳. null이면 들어갈 수 있다.
export function accessRedirect(user: AccessUser | null): '/login' | '/pending' | '/blocked' | null {
  if (!user) return '/login';
  if (user.status === 'blocked') return '/blocked';
  if (user.status === 'pending') return '/pending';
  return null;
}

// 개발 전용 로그인(이메일·비밀번호)은 AUTH_DEV_LOGIN=1이고 앱 주소가 이 컴퓨터일 때만 켠다.
// 배포 주소에서는 켤 수 없다. next start는 NODE_ENV=production이라 그것으로는 나누지 않는다.
export function devLoginEnabled(env: Readonly<Record<string, string | undefined>>): boolean {
  if (env.AUTH_DEV_LOGIN !== '1') return false;
  try {
    const host = new URL(env.BETTER_AUTH_URL ?? '').hostname;
    return host === 'localhost' || host === '127.0.0.1';
  } catch {
    return false;
  }
}

// 관리자가 바꿀 수 있는 상태 변화. 자기 자신은 차단할 수 없다.
export function canSetStatus(
  actor: { id: string; role: UserRole },
  target: { id: string },
  next: UserStatus,
): boolean {
  if (actor.role !== 'admin') return false;
  if (next === 'pending') return false;
  return !(actor.id === target.id && next === 'blocked');
}

// 로그인 뒤 돌아갈 곳(?next=). 같은 사이트 안의 경로만 받는다: /로 시작하고 //나 /\로 시작하지 않으며,
// 인증 화면·API가 아니다. 아니면 홈.
export function safeNextPath(value: unknown): string {
  if (typeof value !== 'string' || !value.startsWith('/') || value.startsWith('//') || value.startsWith('/\\')) return '/';
  if (/^\/(login|pending|blocked|api)(\/|\?|$)/.test(value)) return '/';
  return value;
}
```

```ts
export function createAuth(db: Db, env: AuthEnv = process.env) {

  const google =
    env.GOOGLE_CLIENT_ID && env.GOOGLE_CLIENT_SECRET

    secret: env.BETTER_AUTH_SECRET,
    database: drizzleAdapter(db, { provider: 'sqlite', schema, usePlural: true }),
    socialProviders: google,
    emailAndPassword: { enabled: devLoginEnabled(env) },
    user: {
      additionalFields: {
        status: { type: 'string', required: false, defaultValue: 'pending', input: false },
        role: { type: 'string', required: false, defaultValue: 'user', input: false },
      },
    },
    databaseHooks: {
      user: {
        create: {
          before: async (user) => ({ data: { ...user, ...initialAccess(user.email, admins) } }),
        },
      },
    },
    plugins: [nextCookies()], // 마지막 플러그인이어야 한다(Better Auth 안내)
```

```ts
// 요청의 세션 쿠키로 사용자를 찾는다. 없거나 만료됐으면 null. 상태는 매번 DB에서 읽으므로
// 관리자가 차단하면 다음 요청부터 바로 막힌다(쿠키 캐시를 쓰지 않는다).
export async function getSessionUser(): Promise<CurrentUser | null> {
  // 요청 헤더를 먼저 읽는다. 그래야 빌드(프리렌더) 중에는 여기서 멈추고 인증 객체를 만들지 않는다.
  const requestHeaders = await headers();
  const session = await getAuth().api.getSession({ headers: requestHeaders });
  if (!session) return null;
  const { id, name, email, status, role } = session.user as typeof session.user & {
    status: UserStatus;
    role: UserRole;
  };
  return { id, name, email, status, role };
}

// 화면·Server Action의 입구. 승인된 사용자가 아니면 로그인·승인 대기·차단 화면으로 보낸다.
// 요청을 읽으므로 화면에서는 Suspense 안에서 부른다(Next 16 Cache Components).
export async function requireUser(): Promise<CurrentUser> {
  const user = await getSessionUser();
  const to = accessRedirect(user);
  if (to) redirect(to);
  return user!;
}

export async function requireAdmin(): Promise<CurrentUser> {
  const user = await requireUser();
  if (user.role !== 'admin') redirect('/');
  return user;
}
```

```ts
import { count, eq, sql } from 'drizzle-orm';
import type { Db } from '../db/client';
import { sessions, users, type UserStatus } from '../db/schema';

export interface UserListItem {
  id: string;
  name: string;
  email: string;
  status: UserStatus;
  role: 'user' | 'admin';
  createdAt: Date;
}

// 관리자 화면 목록(화면 규칙 6.3): 승인 대기를 가입이 오래된 순으로 먼저, 나머지는 가입 최신 순.
export function listUsers(db: Db): UserListItem[] {
  return db
    .select({
      id: users.id,
      name: users.name,
      email: users.email,
      status: users.status,
      role: users.role,
      createdAt: users.createdAt,
    })
    .from(users)
    .orderBy(
      sql`case ${users.status} when 'pending' then 0 else 1 end`,
      sql`case ${users.status} when 'pending' then ${users.createdAt} else -${users.createdAt} end`,
    )
    .all();
}

// 요약 줄 "대기 n · 승인 n · 사용 중지 n"(화면 규칙 6.1). 없는 상태는 0.
export function countUsersByStatus(db: Db): Record<UserStatus, number> {
  const counts: Record<UserStatus, number> = { pending: 0, approved: 0, blocked: 0 };
  for (const row of db.select({ status: users.status, n: count() }).from(users).groupBy(users.status).all()) {
    counts[row.status] = row.n;
  }
  return counts;
}

export function countPendingUsers(db: Db): number {
  return db.select({ n: count() }).from(users).where(eq(users.status, 'pending')).get()?.n ?? 0;
}

export function getUserForAdmin(db: Db, id: string): { id: string; status: UserStatus } | undefined {
  return db.select({ id: users.id, status: users.status }).from(users).where(eq(users.id, id)).get();
}

// 상태를 바꾼다. 차단하면 그 사용자의 세션을 모두 지워 바로 로그아웃시킨다.
export function setUserStatus(db: Db, id: string, status: Exclude<UserStatus, 'pending'>): boolean {
  return db.transaction((tx) => {
    const changed = tx.update(users).set({ status }).where(eq(users.id, id)).run().changes > 0;
    if (changed && status === 'blocked') tx.delete(sessions).where(eq(sessions.userId, id)).run();
    return changed;
  });
}
```

3. **로그인 실패(2.3):**
   - Google 콜백 오류는 `/login?error=<코드>`로 돌아온다(`errorCallbackURL: "/login"`).
   - `error === "access_denied"`면 취소 안내(neutral, `role="status"`), 그 밖의 값이면 오류 안내(again, `role="alert"`)다.
   - `Notice`에 `tone`(기본·neutral·error)을 더한다. 오류 코드는 화면에 보이지 않는다.
4. **승인 대기·사용 중지(3·4장):**

5. **상단 바(5장):**
   - 오른쪽 묶음은 [관리 n] · 설정 · 구분선 · 계정 버튼 순서다. `ml-auto`는 관리자면 "관리", 아니면 "설정"에 둔다(`nav-links.tsx`의 설정 `ml-auto`를 옮긴다).
   - 계정 버튼: `Initial` 24px + 이름 + 화살표. 네이티브 `popover`로 이름·이메일·로그아웃을 연다. 640px 아래에서는 이름을 숨기고 `aria-label`을 둔다.
   - "관리"는 현재 위치 표시와 배지가 다른 메뉴와 같다.
6. **관리 화면(6장):**
   - 760px 폭, 요약 줄(`countUsersByStatus`, 0인 항목은 뺌)
   - 대기 묶음 뒤 2px 구분선
   - 칸: 사용자(자기 행 "나" 배지), 상태(`Status`: 대기 wait / 승인 ok / 사용 중지 idle / 관리자 ok "관리자"), 가입("10월 16일 14:32", 올해가 아니면 연도), 동작(대기: 승인 primary + 사용 중지 ghost, 승인됨: 사용 중지 ghost, 사용 중지: 다시 허용 secondary, 자기 행은 비움)
   - 처리 중에는 그 행만 `aria-disabled` + `Status` busy "바꾸는 중"
   - 성공하면 `aria-live`로 알리고, 행은 그 자리에 둔다(다시 정렬하지 않음). 상단 바 배지와 요약 줄은 다시 그린다.
   - 실패하면 상태 아래에 `Failed` "바꾸지 못했습니다"를 둔다.
   - 포커스 처리는 6.5를 따른다.

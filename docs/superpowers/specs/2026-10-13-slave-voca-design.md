# slave-voca 설계서

- 작성일: 2026-10-13
- 상태: 승인됨 (최초안·M1 반영 개정안 모두 2026-10-13 승인, 변경 내용은 13장)
- 관련 제안서: https://claude.ai/code/artifact/6220a7b4-f86c-417b-833d-8e7f3a3414ae

## 1. 목적

논문·발표 자료 PDF에서 어려운 영어 단어를 자동으로 뽑아, 원문 문장 기준의 한국어 뜻과 발음을 붙인 카드로 만들고 간격 반복(SRS)으로 외우게 하는 개인용 웹앱이다.

**성공 기준**

- 텍스트 선택이 가능한 논문 PDF 한 편을 넣고 추출·검토·저장까지 5분 이내
- 저장된 모든 카드에 문맥상 한국어 뜻, 발음기호(사전에 있으면), 발음 듣기, 원문 문장이 있음
- 오늘 복습할 카드만 모아 보여주고, 응답에 따라 다음 복습일이 자동으로 바뀜

## 3. 범위

**1차에 포함:** PDF 업로드, 후보 단어 추출, 검토 화면, 문맥 뜻 생성, 발음기호·발음 듣기, 문서별 단어 목록, SRS 복습, 카드 뜻 수정·삭제, 설정(N, 새 카드 상한)

**1차에서 제외:** 스캔 PDF(OCR), 여러 단어로 된 구문 추출, 배포·로그인, 모바일 화면, 학습 통계, Anki 내보내기

## 4. 사용 흐름

1. **업로드:** 사용자가 PDF와 종류(논문/발표)를 고른다. 제목은 파일명에서 기본값을 채운다.
2. **추출:** 서버가 텍스트를 문장으로 나누고, 후보 단어 목록을 만들어 `candidates`에 저장한다.
3. **검토:** 사용자가 후보 목록에서 아는 단어를 체크 해제하고 "저장"을 누른다.
   - 체크 해제한 단어 → `known_words`에 추가, 이후 모든 추출에서 제외
   - 체크한 단어 → `words`(카드)와 `occurrences`(용례) 생성
4. **뜻·발음 채우기:** 저장 직후 서버가 문맥 뜻과 발음기호를 채운다. 화면은 진행 상태를 보여준다.
5. **복습:** 매일 "오늘의 복습"에서 카드를 보고 모름/애매/앎으로 응답한다.

## 6. 모듈 구조

```
src/
  app/                    Next.js 화면과 Route Handler / Server Action
  lib/
    pdf/parse.ts          PDF → 정제된 문장 배열
    extract/extract.ts    문장 배열 → 후보 단어 목록
    extract/frequency.ts  빈도표 로드, 원형의 순위 조회
    meaning/generate.ts   (단어, 문장) 묶음 → 한국어 뜻 (모델 무관)
    meaning/gemini.ts     Gemini API 구현 (교체 지점)
    phonetic/lookup.ts    단어 → 발음기호 (Free Dictionary API)
    srs/scheduler.ts      응답 → 다음 복습 상태, 오늘의 복습 큐
  server/
    db/schema.ts          Drizzle 스키마
    db/client.ts          DB 연결 (교체 지점)
    repo/*.ts             모든 DB 읽기·쓰기
data/
  frequency.json          원형 → 순위 (빌드 스크립트로 생성)
  frequency-NOTICE.md     빈도표 출처와 라이선스(CC BY-SA 4.0, 8.3)
scripts/
  build-frequency.ts      공개 영어 빈도 목록 → 원형 기준 순위표
```

**원칙:** `lib/` 모듈은 DB를 모르고 입력→출력만 다룬다. DB 접근은 `server/repo/`에서만 한다. 배포로 옮길 때는 `db/client.ts`와 스키마 방언만 바꾼다.

## 7. 데이터 모델

| 테이블 | 컬럼 | 비고 |
|---|---|---|
| `documents` | id, user_id, title, kind(paper/presentation), status(extracting/reviewing/processing/done/error), error_message, created_at | 원본 PDF는 저장하지 않음 |
| `candidates` | id, document_id, lemma, surface, sentence, count, is_existing, in_dictionary | 검토가 끝나면 해당 문서 행 삭제 |
| `words` | id, user_id, lemma((user_id, lemma) unique), phonetic, FSRS 상태(due, stability, difficulty, elapsed_days, scheduled_days, learning_steps, reps, lapses, state, last_review), introduced_at, created_at | 카드 1장 = 단어 1개 |
| `occurrences` | id, word_id, document_id, surface, sentence, meaning_ko, meaning_status(pending/done/failed), created_at | 같은 단어도 문서마다 뜻이 다를 수 있어 뜻은 여기에 저장 |
| `known_words` | user_id, lemma((user_id, lemma) PK), created_at | 추출에서 제외 |
| `review_logs` | id, word_id, rating, reviewed_at | 복습 기록 |
| `settings` | user_id, key((user_id, key) PK), value | `exclude_top_n`=3000, `daily_new_limit`=20 |
| `users`·`sessions`·`accounts`·`verifications` | Better Auth 표. `users`에 status(pending/approved/blocked), role(user/admin) | M6-1. 후보·용례·복습 기록은 문서·단어를 따라 사용자별로 나뉜다(M6-2) |

- 같은 단어가 다른 문서에서 다시 저장되면 `words`는 그대로 두고 `occurrences`만 추가한다. SRS 상태는 초기화하지 않는다.
- 카드 삭제는 `words`와 그 `occurrences`, `review_logs`를 함께 지운다. 삭제한 단어는 `known_words`에 넣지 않는다.

## 8. 처리 규칙

### 8.1 PDF 파싱 (`lib/pdf/parse.ts`)

- `pdfjs-dist`로 페이지별 텍스트를 읽는다.
- 줄 끝 하이픈 복원: `"inter-\nnational"` → `"international"` (하이픈 뒤 줄바꿈이고 다음 글자가 소문자일 때만). **단, 붙인 단어가 실제 단어가 아니고(빈도표에도 없고 원형 기준으로 WordNet 사전에도 없음) 앞뒤 조각이 각각 빈도표에 있으면 하이픈을 남긴다**(`"fine-\ntuning"` → `"fine-tuning"`). 이렇게 남은 단어는 8.2의 2번 규칙대로 합성어로 버려진다. 붙인 단어를 빈도표로만 판정하면 이 앱이 뽑아야 할 드문 단어(`in-\nvariance`, `under-\npin`, `out-\nperform`)까지 합성어로 잃기 때문에 사전도 함께 본다. 빈도표·사전 조회는 함수 인자로 받아 `lib/pdf`가 단어 목록에 직접 의존하지 않게 한다.
- 이메일 주소(`\S+@\S+`)와 URL(`https?://\S+`)을 지운다. 저자 이메일 아이디(`avaswani`)가 후보로 새는 것을 막는다.
- 참고문헌 제목 줄부터 끝까지 버린다. 제목은 대소문자를 구분해 `References`, `REFERENCES`, `Bibliography`, `BIBLIOGRAPHY`, `참고문헌`만 인정하고, 앞에 장 번호(`6 References`, `7. REFERENCES`)가 붙어도 인정한다. 제목이 여러 번 나오면 **마지막** 제목에서 자른다.
- `Intl.Segmenter('en', { granularity: 'sentence' })`로 문장을 나눈다.
- 공백을 제외한 추출 텍스트가 200자 미만이면 실패로 처리한다: "텍스트를 찾지 못했습니다. 스캔 PDF는 지원하지 않습니다."

### 8.2 단어 추출 (`lib/extract/extract.ts`)

1. 문장마다 `/\p{L}+(?:-\p{L}+)*/gu`로 토큰을 뽑는다(유니코드 글자 기준).
2. 3글자 미만, 모두 대문자인 약어(예: `CNN`), 하이픈 복합어, **ASCII가 아닌 글자가 든 토큰**(`Łukasz`)은 버린다. 유니코드 기준으로 뽑은 뒤 버려야 `Łukasz`가 `ukasz` 조각으로 남지 않는다.
3. 소문자로 바꾸고 `wink-lemmatizer`로 원형을 만든다(명사→동사→형용사 순으로 시도해 처음으로 형태가 바뀐 결과, 없으면 그대로).
4. 문장 첫 단어가 아닌 위치에서 **항상 대문자로만** 나온 단어는 고유명사로 보고 버린다. (한계: 문장 첫머리에만 나오는 인명은 거르지 못한다. 검토 화면에서 사용자가 해제한다.)
5. 빈도 순위가 `exclude_top_n` 이하인 단어(표면형 또는 원형)와 `known_words`에 있는 원형을 버린다. 표면형도 보는 이유: `data`의 원형이 `datum`으로 바뀌어 흔한 단어가 새어 나오는 것을 막는다. 빈도표에 없는 원형은 남긴다(전문용어일 가능성이 높음). 학술 핵심어 예외는 없다(M5에서 없앰, 8.7).
6. 원형별로 묶어 등장 횟수와 원문 문장을 기록한다. 원문 문장은 첫 등장 문장을 쓰되, 300자를 넘으면 **단어가 보이도록 단어 주변을 잘라** 300자로 맞춘다(앞뒤로 잘린 쪽에 `…`). `words`에 이미 있으면 `is_existing=true`.
7. **복수형 보정:** 원형이 `s`로 끝나고(`ss`로 끝나는 것은 제외) `s`를 뗀 형태가 같은 문서의 후보에 있으면, 그 후보에 횟수를 합친다(`datasets` → `dataset`). 원문 문장은 합쳐지는 쪽(`dataset`)의 것을 유지한다.
8. **사전 확인:** 원형이 영어 단어 목록(`wink-lexicon`의 WordNet 단어 77,262개, MIT 라이선스, 이미 설치됨)에 있으면 `in_dictionary=true`. 없으면 검토 화면에서 기본 체크 해제하고 "사전에 없음"을 표시한다. 버리지는 않는다. 알려진 한계: `dataset`, `encoder`, `embedding` 같은 최신 전문용어도 사전에 없음으로 나온다. 반대로 `err`, `std`는 사전에 있어 그대로 통과한다.
9. 등장 횟수 내림차순, 같으면 알파벳순으로 정렬한다.
10. 빈도표 조회는 객체의 프로토타입 키(`constructor` 등)에 반응하지 않아야 한다.

### 8.3 빈도표 (`scripts/export-wordfreq.py`, `scripts/build-frequency.ts`)

- 입력: `wordfreq` 3.1.1(데이터 CC BY-SA 4.0)의 영어 빈도순 단어에서 알파벳 소문자 단어만 골라 앞에서 20,000개. 순위는 거른 뒤의 위치다. (M5에서 `first20hours/google-10000-english`에서 교체: 원본이 상업적 사용에 LDC 라이선스를 요구한다.)
- `npm run freq:build`: Python 스크립트가 `data/wordfreq-en.txt`(커밋 안 함)를 쓰고, TS 스크립트가 각 단어와 그 원형(8.2의 3번 방식)을 둘 다 키로 넣어 키별 **가장 높은 순위**를 `data/frequency.json`(커밋함, 20,464개 항목)으로 저장한다. 앱·테스트·CI에는 Python이 필요 없다.
- 출처 표시: `data/frequency-NOTICE.md`(wordfreq와 SUBTLEX·Google Books Ngram·OpenSubtitles 인용, 파생 파일의 CC BY-SA 4.0). README 데이터 출처 표.
- N 기본값은 3,000이다. 논문에는 일상어가 드물어, 학술 핵심어 예외 없이도 hence, whereas, respectively, subsequent, substantial 등이 남는다(M5 실측: 목표 15개 중 11개, 편당 후보 255~278개). 놓치는 것: novel, adopt, despite, widely. 대신 accuracy, algorithm 같은 쉬운 기술어가 처음 몇 편에 섞이고, "안다"로 정리하면 빠진다.

### 8.4 문맥 뜻 생성 (`lib/meaning/generate.ts`)

- `@google/genai`(2.24.0 고정), 모델 `gemini-3.5-flash-lite`(사용자 결정, 2026-10-16), `thinkingConfig.thinkingLevel: LOW`(2026-10-16 M4-4 실측: MINIMAL보다 문맥 오답이 적고 비용은 같다), `maxOutputTokens: 16384`(200개 묶음 출력이 실측 약 5,500토큰이라 8192로는 여유가 적다).
- 모델 선택 이유(2026-10-16 실측): `gemini-3.6-flash`는 유료 등급에서도 503 과부하로 요청 7번 중 6번이 실패해 논문 한 편의 뜻 200/211이 비었다. 같은 조건에서 `gemini-3.5-flash-lite`는 attention 논문 211개를 13.9초에 실패 0으로 채웠고, 표본 20개 중 문맥 오답은 1개였다. `gemini-2.5-flash-lite`는 새 키로는 쓸 수 없고("예전에 쓴 사용자"만 허용), `gemini-3.1-flash-lite`는 2027-05-07 종료 예정이다.
- 가격(공식): 입력 $0.30 / 출력 $2.50(100만 토큰당, 출력에 사고 토큰 포함). 실측으로 논문 한 편(단어 211개)에 약 $0.018 (M4-4 설정에서 $0.013~0.015). 키는 유료 등급(선불 $5, 잔액이 0이면 키가 멈춤)이다. 무료 등급은 분당 5요청 한도가 있고 입력을 Google이 제품 개선에 쓰므로 쓰지 않는다.
- 모델 교체 지점: `MeaningModel` 함수 형태만 지키면 다른 모델로 바꿀 수 있다. 화면·DB·`generate.ts`는 바뀌지 않는다.
- 한 요청에 최대 50개의 (id, 단어, 원문 문장)을 담고, 묶음은 최대 5개까지 동시에 보낸다. 논문 한 편(후보 약 200개)이 한 번에 나간다. 결과 순서는 묶음 순서다. (2026-10-16 M4-4에서 200개 순서대로 보내기에서 변경: 50개 묶음이 실측에서 틀린 뜻이 적었다. 200개는 무료 등급 분당 5요청 한도 때문이었는데 유료 등급 키라 그 제약이 없다.)
- 구조화 출력(`responseMimeType: "application/json"` + `responseJsonSchema`)으로 `{ meanings: [{ id, meaning_ko }] }`를 받고, zod로 한 번 더 검증한다. 응답이 비었거나(차단 등) 형식이 틀리면 그 묶음은 실패로 처리한다.
- **깨진 글자 검사:** 뜻에 한글 낱자모(첫가끝 U+1100–11FF, 호환 자모 U+3130–318F)가 섞이면 그 묶음을 실패로 보고 재시도 대상에 넣는다. (2026-10-16 실측: 200개 묶음 응답이 "머커뉴ᄆ"처럼 자모로 흩어져 와도 형식은 정상이라 "완료"로 저장되는 일이 있었다.)
- 시스템 지시(2026-10-16 보강, 실험 B1): 학술 논문 문맥임을 밝히고 (1) 사전 첫 뜻이 아닌 문장 속 의미 (2) 한국어 학술 글의 관용 전문 용어 우선, 일상어 뜻 금지 (3) 여러 단어로 된 용어·연어의 일부면 표현 전체의 뜻 기준 (4) 품사 형태(동사 "~하다", 형용사 "~한"), 명사가 앞 단어를 꾸미면 그 용어 안의 뜻 (5) 모든 id에 하나씩, 2~15자. 예시(few-shot)는 넣지 않는다(실험에서 특정 해석으로 쏠림). 근거: attention 200개 묶음 2회 비교에서 기존 지시는 progression을 "진행"으로 틀리고 1회는 출력이 깨졌으며, 보강 지시는 고정 40개 중 평균 38.5개 맞음.
- API 키는 환경변수 `GEMINI_API_KEY`(`.env.local`)에서 읽고, 서버에서만 사용한다.
- **재시도:** 묶음 요청이 HTTP 429, 503, 그 밖의 5xx나 네트워크 오류로 실패하면 1→2→4초 지수 백오프(지터 포함)로 최대 3번 다시 보낸다. 400·401·403·404는 재시도하지 않는다. (2026-10-15 실측: attention 논문에서 묶음 5개 중 3개가 503 "high demand"로 실패해 뜻의 53%가 비었다.)
- 응답에 빠진 id나 요청 실패는 해당 용례를 `meaning_status=failed`로 둔다. 문서 단어 목록에서 재시도할 수 있다.
- SDK 사용법은 `@google/genai` 공식 문서(googleapis.github.io/js-genai)를 따른다.

### 8.5 발음기호 (`lib/phonetic/cmudict.ts`, `lib/phonetic/arpabet.ts`, `data/cmudict.txt`)

- CMU Pronouncing Dictionary(BSD 2-clause, 미국식 발음)에서 원형으로 찾는다. 여러 발음이 있으면 첫 번째를 쓴다. ARPAbet 표기를 IPA로 바꿔 `/.../` 형태로 저장한다. 강세 기호(ˈ, ˌ)는 최대 두음 규칙으로 강세 모음 앞 자음군 앞에 붙인다. 없으면 `phonetic=null`(발음 듣기는 그대로 된다).
- CMUdict 조회 자체가 실패하면(파일 없음 등) 저장을 오류로 만들지 않고 발음기호 없이 둔다. 로그는 한 번만 남긴다.
- CMUdict 데이터는 빌드 스크립트(`scripts/build-cmudict.ts`)가 고정 커밋의 원본에서 알파벳 소문자 단어의 첫 발음만 남긴 ARPAbet 목록(`data/cmudict.txt`, 약 11만 7천 단어, 3MB)으로 만들어 커밋한다. IPA 변환은 조회할 때 한다. 파일은 번들에 넣지 않고 서버에서 처음 쓸 때 한 번 읽는다. 저작권 고지는 `data/cmudict-LICENSE`로 함께 둔다.
- (M5에서 없앰) Free Dictionary API(`dictionaryapi.dev`) 보조: 이용 조건이 명시돼 있지 않고, 실측에서 CMUdict에 없는 단어(후보의 약 13%, regularization, softmax 등 전문어)를 하나도 채우지 못했다.

### 8.6 SRS (`lib/srs/scheduler.ts`)

- `ts-fsrs`(5.4.2 고정) 기본 파라미터를 쓰되, 퍼즈(복습일 무작위 흔들기)는 끈다(`enable_fuzz: false`). 같은 응답이면 같은 일정이 나와 테스트와 예측이 쉽다. 응답은 모름→Again, 애매→Hard, 앎→Good에 대응한다.
- **오늘의 큐:** (1) `state != New`이고 `due <= 지금`인 카드, due 오름차순 + (2) 새 카드 중 `created_at` 오름차순으로 `daily_new_limit - 오늘 처음 본 새 카드 수`장
- 새 카드를 처음 응답하면 `introduced_at`을 기록한다. "오늘"은 로컬 자정을 기준으로 한다.
- 큐는 복습 화면을 열 때 계산하고, 응답할 때마다 서버에 저장한다. Again을 받은 카드는 같은 세션 끝에 다시 보여준다.

### 8.7 학술 핵심어 목록 (M5에서 없앰)

- M2~M4에서는 Coxhead의 Academic Word List(AWL) 대표어 570개로, 빈도 순위 2,001 이상인 학술 핵심어를 기준 N 안이어도 남겼다.
- AWL은 이용 조건이 밝혀져 있지 않아(대학 페이지에는 저작권 표시만 있음) 상업적으로 쓸 수 없다. 2026-10-16 저장소 공개 때 목록을 저장소와 기록에서 지웠고, M5에서 예외 규칙과 코드도 없앴다. 그 대신 N 기본값을 3,000으로 낮췄다(8.3).
- 대안 실측(M5 설계서 2장): NAWL(CC BY-SA 4.0)은 목표 단어가 없어 보탬이 없었고, arXiv 초록(CC0)으로 만든 목록은 쉬운 주제어를 너무 많이 끌어왔다.

## 9. 오류 처리

| 상황 | 처리 |
|---|---|
| PDF가 아님, 50MB 초과 | 업로드 거부, 메시지 표시. 50MB 초과는 폼에서 제출 전에 막는다. PDF 판별은 앞 1,024바이트 안에 `%PDF-`가 있으면 인정한다(PDF 규격이 허용하는 앞쪽 쓰레기 바이트 대응) |
| 텍스트 없음(스캔 PDF) | 문서 `status=error`, 사유 표시 |
| 후보 0개 | 검토 화면에 "외울 단어가 없습니다" 표시, 문서는 `done` |
| `GEMINI_API_KEY` 없음 | 카드는 저장하고 뜻은 `failed`, 화면에 키 설정 안내 |
| Gemini API 실패, 응답 누락·차단 | 해당 용례 `failed`, 재시도 버튼 |
| CMUdict에 없음·조회 실패 | 발음기호만 비움, 발음 듣기는 유지 |
| 브라우저 TTS 없음 | 발음 버튼 숨김 |

## 10. 테스트

  - `repo`: 메모리 SQLite로 같은 단어 재저장 시 용례만 추가, 카드 삭제 연쇄
- **수동 확인:** 실제 논문 PDF 3편(1단 1편, 2단 2편)으로 추출 품질과 처리 시간 5분 이내를 확인한다.

## 12. 열린 항목

- Gemini API 키 발급 여부: 아직 없다(2026-10-13 확인). Google AI Studio에서 무료로 발급할 수 있다. 키가 없어도 마일스톤 2의 추출 개선, 저장, 발음기호는 진행할 수 있다. 뜻 생성은 테스트에서 SDK를 목으로 대체하고, 실제 호출 확인만 키를 받은 뒤 한다.
- (M5에서 해결) AWL 라이선스: 학술 핵심어 예외를 없앴다(8.7). 상업적 이용 허락을 받으면 다시 넣을 수 있다.

## 0. 지금 화면에서 본 것

데모 DB(`data/demo.db`)로 띄운 실제 화면에서 확인했다.

1. **다크 모드가 반쯤만 적용된다.** `globals.css`는 `prefers-color-scheme: dark`일 때 배경을 검게 바꾸지만, 컴포넌트는 `bg-blue-100`, `bg-yellow-50`, `bg-black` 같은 라이트 전용 색을 그대로 쓴다. 시스템이 다크이면 다음처럼 보인다.
   - 복습 카드의 "새 카드" 배지가 하늘색 막대로만 보이고 글자가 안 보인다.
   - 문서 단어 목록의 API 키 안내 상자가 크림색 바탕에 흰 글자라서 읽을 수 없다.
   - 주 버튼(`bg-black`)이 배경과 같은 색이라 버튼으로 보이지 않는다.
2. **문서 단어 목록에서 "문맥 뜻" 열이 한 글자 폭으로 눌린다.** "실패"가 세로로 쪼개져 나온다. 표에 열 너비가 지정되어 있지 않아서 생기는 일이다.
3. **원문 강조가 형광 노랑 `<mark>`라서** 한 화면에 수십 개가 있으면 눈에 많이 걸린다(특히 다크 바탕).
4. 글꼴이 `Arial, Helvetica`로 고정되어 있다. 한글은 OS 기본 글꼴로, IPA 기호는 브라우저가 고르는 대체 글꼴로 나온다.
5. 검토 대기 문서는 데모 DB에 남아 있지 않았다(두 문서 모두 "완료"). 검토 화면 목업은 Transformer 논문 초록의 실제 문장으로 만들었다.

## 1. 글꼴 검증: IPA를 다 지원하는 글꼴은 생각보다 적다

이 앱이 실제로 내보내는 IPA 기호를 모아 후보 글꼴 파일의 cmap을 직접 검사했다(fontTools, Google Fonts 저장소 원본과 Pretendard 1.3.9).

- **필수 18자**: CMUdict 변환표(`src/lib/phonetic/arpabet.ts`)가 쓰는 기호 전체이고, 데모 DB의 발음기호에 실제로 들어 있는 비ASCII 문자와 같다.
  `ˈ ˌ ə ɪ ɚ ʒ ʃ ɔ ʌ ɛ ɡ æ ʊ ɑ ɝ θ ŋ ð`
- **추가 13자**: Free Dictionary API가 영국식 표기로 줄 수 있는 기호다.
  `ɒ ɜ ː ɹ ɾ ɐ ᵻ ɫ ʔ ɘ ɵ ʉ ɨ`

| 글꼴 | 필수 18자 | 추가 13자 | 한글 | 판정 |
|---|---|---|---|---|
| **Pretendard** | 전부 | ᵻ만 없음 | 있음 | 한글·UI·IPA를 한 벌로 처리할 수 있다 |
| Inter | 전부 | ᵻ만 없음 | 없음 | 쓸 수 있다 |
| **Gentium Book Plus** | 전부 | 전부 | 없음 | SIL이 언어학 표기용으로 만든 세리프. IPA에 가장 안전하다 |
| Charis SIL, Noto Sans, Noto Serif, Noto Sans Mono, Andika | 전부 | 전부 | 없음 | 쓸 수 있다 |
| EB Garamond | 전부 | ᵻ만 없음 | 없음 | 쓸 수 있다 |
| Source Code Pro | ɝ 없음 | ᵻ 없음 | 없음 | 쓸 수 없다 |
| Source Serif 4, Literata | ɪ ʃ ʊ 등 9자 없음 | 대부분 없음 | 없음 | 쓸 수 없다 |
| Newsreader, IBM Plex Serif, Crimson Pro, Fraunces | 12~14자 없음 | 없음 | 없음 | 쓸 수 없다 |
| JetBrains Mono, Fira Mono, IBM Plex Mono | 13~15자 없음 | 없음 | 없음 | 쓸 수 없다 |
| Noto Sans KR, Noto Serif KR, IBM Plex Sans KR, SUIT | 대부분 없음 | 없음 | 있음 | 한글 전용으로만 쓸 수 있다 |

결론은 세 가지다.
- 논문 느낌으로 흔히 고르는 Source Serif 4와 Newsreader는 발음기호 칸에서 글꼴이 섞여 깨진다. 세리프를 쓴다면 **Gentium Book Plus**가 맞다.
- 고정폭 글꼴은 발음기호에 쓰지 않는다.
- `ᵻ`(Pretendard와 Inter에 없음)는 드물다. 대체 글꼴 목록 끝에 Gentium이나 Noto Sans를 두면 해결된다.
- **`θ`는 그리스 문자(U+03B8)다.** `next/font/google`로 불러올 때 `latin-ext`와 함께 **`greek` 하위 집합을 넣어야 한다.** 빠뜨리면 θ만 대체 글꼴로 나온다.

## 2. 디자인 방향 3안

세 안은 바탕 톤, 글꼴, 밀도를 서로 다르게 잡았다. 비교 목업은 `mockups/directions.html`이다.

### A안 「지면」: 논문을 읽던 그 지면이 카드가 된다 (추천)

- **분위기**: 따뜻한 종이색 바탕과 먹색 글자. 강조색은 잉크 파랑 하나. PDF 리더나 종이 논문에 가깝다.
- **색**: 바탕 `#F4F1EA`, 면 `#FBFAF7`, 글자 `#22201C`, 강조 `#2F5D8C`, 형광펜 `#F0DB8C`. 다크는 따뜻한 먹색 바탕 `#171614`.
- **글꼴**: 영어 단어·원문 문장·IPA는 **Gentium Book Plus**, 한글 뜻과 UI는 **Pretendard**. 세리프(영어)와 고딕(한글)이 갈라져서 "원문"과 "내 말(뜻)"이 글꼴만으로 구분된다.
- **밀도**: 보통. 복습은 여유 있게, 검토 표는 한 줄 행(38px)으로 조밀하게.
- **장점**: 이 앱의 차별점인 "그 논문의 그 문장"이 화면에서 정말 논문 문장처럼 보인다. 오래 봐도 피곤하지 않은 낮은 대비의 바탕이다. 차분하지만 "디자인이 없는" 느낌은 아니다.
- **단점**: 같은 크기면 세리프가 고딕보다 조금 넓어서, 검토 표에서 한 화면에 보이는 행이 B보다 2~3행 적다. Gentium은 굵기가 Regular·Bold 두 가지뿐이라 굵기 단계를 섬세하게 나눌 수 없다.

### B안 「작업대」: 조밀하고 빠른 도구

- **분위기**: 흰 바탕, 회색 선, 고딕 한 벌. 개발 도구나 스프레드시트처럼 정보 위주이고 키보드 중심이다.
- **색**: 바탕 `#FFFFFF`, 면 `#F7F7F8`, 선 `#E4E4E7`, 글자 `#18181B`, 강조 인디고 `#4C5BD4`. 강조 표시는 형광펜이 아니라 연한 인디고 칠.
- **글꼴**: **Pretendard** 한 벌(영어·IPA 포함), 숫자는 고정폭 숫자(`tabular-nums`).
- **밀도**: 높음. 검토 표는 32px 행에 문장 한 줄 말줄임이라 한 화면에 25행 이상 보인다.
- **장점**: 검토 속도가 가장 빠르다. 글꼴 하나라 구현과 유지가 가장 쉽다. 배포했을 때 다른 사용자에게도 무난하다.
- **단점**: 복습 카드가 서식(라벨: 값)처럼 보여 단어장으로서의 맛이 없다. 원문을 한 줄로 자르면 문맥의 핵심 정보가 잘린다. 개성이 적다.

### C안 「야간 집중」: 한 장씩, 어둡게, 크게

- **분위기**: 어두운 바탕이 기본이다. 가운데 정렬의 큰 글자, 강조색은 호박색 하나. 밤에 침대 옆 스탠드를 켠 느낌. 복습 중에는 내비게이션을 숨기는 집중 모드.
- **색**: 바탕 `#111317`, 면 `#1A1D23`, 글자 `#E8E6E1`, 강조 `#E3A857`. 라이트 모드는 보조로 둔다.
- **글꼴**: 영어·IPA는 **Inter**(큰 크기용 광학 크기 지원), 한글은 **Pretendard**(Inter 기반이라 섞여도 자연스럽다).
- **밀도**: 낮음. 검토도 카드형 목록(단어 줄 + 문장 줄)이다.
- **장점**: 복습 몰입감이 가장 좋다. 밤에 눈부심이 적다. 첫인상이 가장 "앱 같다".
- **단점**: 검토 화면이 한 화면에 8행 안팎이라 200개를 훑으려면 스크롤이 길다. 낮에 흰 바탕 PDF와 오가면 밝기 차이가 크다. 형광펜 대신 밑줄만 쓰므로 강조가 약하다.

### 추천: A안. 단, 검토 표는 B안의 밀도와 키보드 방식을 가져온다

이 앱이 일반 단어장과 다른 점은 문맥이다. A안은 그 문맥(원문 문장)을 가장 잘 살린다. A의 약점인 검토 밀도는 표를 한 줄 행으로 만들고 J/K·Space 조작을 붙여 상당 부분 메운다(목업 3번 화면). 다크 모드도 1차부터 넣기를 권한다. 데모 화면이 다크로 그려진 것을 보면 사용자의 시스템이 다크 설정일 가능성이 높고, 지금 깨지는 부분도 대부분 다크 모드에서 생긴다.

사용자가 B나 C를 고르면 3장의 토큰 이름은 그대로 두고 값만 바꾸면 된다. 4~8장의 화면 구성과 상호작용 규칙은 세 안에 공통으로 적용된다.

## 3. 추천안 디자인 토큰

### 3.1 색

의미 이름으로 정의하고, 라이트와 다크는 같은 이름에 다른 값을 넣는다. 대비는 WCAG AA(본문 4.5:1) 이상을 목표로 골랐다.

| 토큰 | 용도 | 라이트 | 다크 |
|---|---|---|---|
| `bg` | 페이지 바탕 | `#F4F1EA` | `#171614` |
| `surface` | 카드·표·입력 면 | `#FBFAF7` | `#1F1E1B` |
| `sunken` | 눌린 면, 진행 막대 바탕, 선택된 탭 | `#EEEAE1` | `#141311` |
| `line` | 구분선 | `#E2DDD2` | `#2F2D29` |
| `line-strong` | 입력 테두리, 표 머리 | `#CEC7B8` | `#403D37` |
| `ink` | 본문 글자 | `#22201C` | `#ECE7DD` |
| `ink-2` | 원문 문장, 보조 본문 | `#4A463F` | `#CFC9BD` |
| `muted` | 설명, 메타 정보, IPA | `#6E685E` | `#A29B8E` |
| `faint` | 비활성, 해제된 행 | `#857E72` | `#807A70` |
| `accent` | 주 버튼, 링크, 포커스 | `#2F5D8C` | `#8DB4DE` |
| `accent-soft` | 포커스 행, "이미 학습 중" 배지 | `#E6EDF5` | `#223041` |
| `on-accent` | 주 버튼 글자 | `#FFFFFF` | `#10161E` |
| `mark` | 원문 속 단어 형광펜(아래 45%만 칠함) | `#F0DB8C` | `rgb(222 178 64 / .32)` |
| `again` / `again-soft` | 모름, 실패, 오류 | `#A6463B` / `#F5E3DF` | `#E08A7E` / `#3A2421` |
| `hard` / `hard-soft` | 애매, 안내 줄 | `#7F5A0C` / `#F3E9D0` | `#D9B45E` / `#352B16` |
| `good` / `good-soft` | 앎, 완료, 새 카드 | `#3B7150` / `#E0EEE4` | `#8CC79C` / `#1E3225` |

`globals.css` 적용 예(Tailwind 4, 설정 파일 없음).

```css
@import "tailwindcss";

:root {
  --bg: #F4F1EA; --surface: #FBFAF7; /* … 위 표의 라이트 값 … */
  color-scheme: light;
}
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { --bg: #171614; /* … 다크 값 … */ color-scheme: dark; }
}
:root[data-theme="dark"] { --bg: #171614; /* … 다크 값(위와 같음) … */ color-scheme: dark; }

@theme inline {
  --color-bg: var(--bg);
  --color-surface: var(--surface);
  --color-ink: var(--ink);
  --color-accent: var(--accent);
  /* … 표의 모든 토큰 … */
  --font-sans: var(--font-pretendard), system-ui, sans-serif;
  --font-en: var(--font-gentium), "Noto Serif", Georgia, serif;
}
```

컴포넌트에서는 `bg-surface text-ink border-line`처럼 쓴다. `dark:` 변형은 쓰지 않는다. 테마를 바꾸는 것은 변수뿐이라 다크 누락이 구조적으로 생기지 않는다. `data-theme`는 M4 설정 화면에서 테마를 고를 때를 위해 미리 열어 둔다. 지금은 시스템 설정을 따른다.

### 3.2 글꼴

| 역할 | 글꼴 | 불러오기 |
|---|---|---|
| UI, 한글 뜻, 숫자 | Pretendard Variable | `pretendard` npm 패키지의 `PretendardVariable.woff2`를 `next/font/local`로. Google Fonts에 없다. 약 2MB이지만 로컬 앱이라 문제없고, 배포할 때는 dynamic subset으로 바꾼다 |

공통 규칙: 한글 문단에 `word-break: keep-all`, 숫자 열에 `font-variant-numeric: tabular-nums`.

복습 카드에서 크기가 단어 → 문맥 뜻 → 원문 순으로 줄어들게 했다. 뜻(22, 고딕 굵게)과 원문(18, 세리프)은 글꼴과 굵기가 달라서 크기 차이가 작아도 서로 섞이지 않는다.

### 3.4 간격, 모서리, 그림자, 움직임

- **간격**: 4px 단위. Tailwind 기본 눈금(`1`=4px)을 그대로 쓴다. 주로 쓰는 값은 4, 8, 12, 16, 20, 24, 32, 40.
- **페이지 폭**: 표 화면은 최대 1200px, 좌우 여백 40px. 복습은 760px 가운데 정렬.
- **모서리**: `sm` 4px(배지, 체크박스, kbd), `md` 7px(버튼, 입력), `lg` 10px(패널, 카드, 답 버튼).
- **그림자**: `shadow-1` = `0 1px 2px rgb(34 32 28 / .06), 0 1px 1px rgb(34 32 28 / .04)`(패널), `shadow-2` = `0 4px 16px rgb(34 32 28 / .08), 0 1px 3px rgb(34 32 28 / .06)`(대화상자). 다크에서는 검은 그림자를 짙게 하고 면 색 차이로 층을 나눈다.
- **포커스**: 모든 조작 요소에 `outline: 2px solid var(--accent); outline-offset: 2px`(`:focus-visible`).
- **움직임**: 150ms 이하 색 전환과 처리 중 회전 표시 정도만. 카드 뒤집기 애니메이션은 넣지 않는다(하루 수백 번 반복되는 동작이라 0.3초도 쌓이면 길다). `prefers-reduced-motion`이면 회전도 멈춘다.

## 4. 공통 레이아웃과 부품

### 4.1 레이아웃 (`layout.tsx`)

- 상단 바 52px, 면 색 바탕에 아래 구분선. 왼쪽 끝에 작업명 "slave-voca"를 작은 회색 글씨로 두고, 이어서 **홈 · 복습 · 문서**, 오른쪽 끝에 **설정**(M4)을 둔다. 작업명을 크게 내세우지 않아서 나중에 이름이 바뀌어도 레이아웃이 그대로다.
- 현재 위치 메뉴는 `sunken` 바탕과 굵은 글씨로 표시한다(`aria-current="page"`). 이를 위해 내비게이션을 작은 클라이언트 컴포넌트로 분리해야 한다(`usePathname`).
- 본문 래퍼(`max-w-5xl`)는 레이아웃에서 빼고 페이지마다 정한다(표는 넓게, 복습은 좁게).

### 4.2 부품

새 컴포넌트 라이브러리(shadcn/ui 등)는 **넣지 않기를 권한다.** 화면이 6~7개이고 필요한 부품도 적다. Tailwind 클래스와 토큰으로 `src/components/ui/`에 직접 만드는 편이 의존성과 스타일 충돌이 적다. M4에서 쓸 대화상자는 브라우저 기본 `<dialog>`(포커스 가두기와 Esc 처리를 기본 제공)로 충분하다. 아이콘은 발음 버튼과 업로드 아이콘 두세 개뿐이니 인라인 SVG로 둔다. 아이콘이 늘어나면 그때 `lucide-react`를 검토한다.

| 부품 | 변형 | 비고 |
|---|---|---|
| `Button` | primary, secondary, ghost, danger / sm, md | 단축키가 있으면 오른쪽에 `Kbd`를 붙인다 |
| `Kbd` | — | 단축키 표시. 버튼 안에서는 버튼 글자색을 따른다 |
| `Tag` | learning(이미 학습 중), nodict(사전에 없음, 점선 테두리), new(새 카드) | 칠하는 배지는 두 가지까지만. "사전에 없음"은 테두리만 둔다 |
| `Status` | ok, wait, busy, err | 점 + 글자. busy는 작은 회전 고리 |
| `Notice` | — | 왼쪽 3px 색 줄 + 면 색 바탕. 화면 전체를 경고색으로 칠하지 않는다 |
| `MeaningCell` | done, pending, failed, editing | 7장 상태 규칙을 한곳에 모은다 |
| `Highlight` | — | 기존 `lib/text/highlight`의 결과를 `<mark>`로 그린다. 형광펜은 글자 아래쪽 45%만 칠한다 |
| `Segmented` | — | 업로드 종류(논문/발표), 설정의 테마 |
| `DataTable` 스타일 | — | 표 머리 12px 회색, 행 구분선, 마우스를 올리면 sunken |

## 5. 화면별 개편안

목업 번호는 `a-paper.html`의 섹션 번호다.

### 5.1 홈 `/` (목업 1)

- 왼쪽 패널 "오늘의 복습": 날짜, 큰 숫자 두 개(복습할 카드 / 새 카드), **복습 시작** 주 버튼(`Enter`). 0장이면 숫자 대신 "오늘 복습할 카드가 없습니다"를 쓰고 버튼은 숨긴다.
- 오른쪽 패널 "최근 문서": 제목(세리프), 상태 점, 종류·단어 수·날짜를 한 줄로. 오른쪽 위에 "PDF 올리기" 링크.
- 뜻 생성 실패가 있으면 아래에 조용한 안내 줄(`Notice`)을 하나 둔다. "단어와 원문 문장은 그대로 복습할 수 있습니다"라고 덧붙여, 실패가 복습을 막지 않는다는 점을 알린다.
- 최근 문서의 단어 수·실패 수와 안내 줄은 데이터가 더 필요하다(9장 제안 1).

### 5.2 문서 목록 `/documents` (목업 2)

- 업로드 폼은 점선 테두리의 한 줄 드롭 영역이다. "PDF를 끌어다 놓거나 파일 선택 · 50MB까지", 종류는 `Segmented`(논문/발표), 제목 입력, **올리기**. 끌어다 놓기도 받는다. 같은 `<input type=file>`에 연결하니 흐름은 그대로다. 추출 중에는 버튼이 "단어 추출 중…"과 회전 표시로 바뀐다.
- 표의 열은 제목(세리프 링크) / 종류 / 상태(`Status`) / 단어(오른쪽 정렬, 검토 대기면 "후보 212") / 올린 날.
- 오류 문서는 제목 아래에 사유를 회색 작은 글씨로 쓰고, 상태 열에만 빨간 점을 둔다. 뜻 실패가 있는 완료 문서는 제목 아래에 점선 표시와 함께 "뜻 206개 생성 실패"를 쓴다.
- 행 전체를 클릭할 수 있게 한다(지금은 제목 링크만 된다).

### 5.3 검토 `/documents/[id]/review` (목업 3, 3-1). 오래 쓰는 화면

목표는 200개를 몇 분 안에 훑는 것이다.

- **도구줄 고정**: 스크롤해도 위에 붙어 있다. "212개 중 **194**개 저장 · 해제한 18개는 아는 단어로", (제안) 필터 칩, "전체 해제/전체 선택", **저장** `Ctrl+Enter`.
- **행은 한 줄**: 체크박스 / 단어(세리프 굵게) + 배지는 같은 줄 / 횟수(오른쪽 정렬, 회색) / 원문 문장(세리프, 강조). 배지를 단어 옆에 두어 행 높이가 일정하다. 원문은 추출 단계에서 이미 단어 주변만 잘라 두었기 때문에(8.2) 보통 한두 줄이다.
- **해제한 행은 흐리게**: 단어 굵기를 빼고 문장과 형광펜을 옅게 한다. 무엇을 "아는 단어"로 보낼지 스크롤하면서 한눈에 보인다. 취소선은 읽기 방해가 커서 쓰지 않았다.
- **배지 구분**: "이미 학습 중"은 강조색으로 칠한 배지(정보), "사전에 없음"은 점선 테두리 배지(의심)로 모양 자체를 다르게 했다. 사전에 없는 단어는 기본 해제라서 대부분 흐린 행 안에 있게 된다.
- **키보드**: `J`/`K`(또는 ↓/↑)로 포커스 행 이동, `Space`나 `X`로 체크 전환, `Ctrl+Enter`로 저장. 포커스 행은 `accent-soft` 바탕과 왼쪽 3px 막대로 표시한다. 표 아래에 단축키 안내 줄을 상시 둔다.
- **저장 중(약 10초)**: 도구줄이 "뜻과 발음을 채우는 중 · 194개"와 진행 막대로 바뀌고, 표는 반투명하게 덮어 잠근다. "보통 10초 안팎 걸립니다. 끝나면 단어 목록으로 이동합니다." 진행 막대는 실제 진행률이 없으니 **무한 진행 표시**(줄무늬나 왕복)로 그린다. 목업의 62%는 그림일 뿐이다. `aria-live="polite"`로 상태를 읽어 준다.
- 0개일 때: "외울 단어가 없습니다"와 문서 목록으로 돌아가는 링크.

### 5.4 문서 단어 목록 `/documents/[id]` (목업 4)

- 머리: 작은 "문서" 라벨, 제목(세리프 26px), 메타(종류 · 단어 수 · 올린 날).
- 뜻 실패가 있으면 `Notice` 한 줄: "뜻 206개를 만들지 못했습니다 · GEMINI_API_KEY 없음. .env.local에 키를 넣고 서버를 다시 시작한 뒤 [모두 다시 시도]". 재시도 버튼은 M4.
- 열은 3개로 줄인다: **단어**(단어 + 아래 줄에 IPA) / **문맥 뜻**(고정 260px, 한글 굵게 15px) / **원문 문장**. 발음기호를 단어 칸에 넣어서 뜻 칸이 눌리는 문제(0장 2번)를 없애고, 뜻을 두 번째 열로 끌어올린다.
- 상태: 뜻 실패는 "– – 생성 실패 · 다시 시도"(점선 + 회색 글자), 생성 중은 회전 고리 + "뜻 만드는 중", 발음기호 없음은 IPA 자리에 옅은 회색 "발음기호 없음"(지금의 "—"보다 의미가 분명하다).
- M4: 행에 마우스를 올리면 뜻 칸 아래에 "뜻 고치기 · 카드 삭제" 링크가 나타난다. 뜻 고치기는 그 자리에서 입력칸으로 바뀌고 `Enter` 저장, `Esc` 취소. 카드 삭제는 확인 대화상자를 띄운다(목업 6).

### 5.5 복습 `/study` (목업 5, 5-1). 오래 쓰는 화면

목표는 키보드만으로, 손과 눈의 이동 없이 끝까지 가는 것이다.

- **진행 줄**: 위에 "12 / 206", 얇은 진행 막대, "남은 194". 지금의 "남은 카드 N장" 텍스트를 대체한다. 모름 카드가 큐 뒤로 다시 들어가므로 분모는 "응답 수 + 남은 수"로 계산한다.
- **카드(앞면)**: 760px 폭 가운데, 높이 380px 고정. 왼쪽 위에 "새 카드" 배지(good 색), 단어 52px 세리프와 둥근 발음 버튼. 카드 아래쪽에 옅은 안내문 "이 문서에서 어떤 뜻이었는지 떠올려 보세요". 앞면에 문맥 힌트를 줄지는 9장 제안 4.
- **뒷면 보기**: 카드 바로 아래 전체 폭 버튼 "뒷면 보기 `Space`". 뒷면을 열면 같은 자리에 답 버튼 세 개가 나온다. 마우스로 하더라도 손이 같은 위치에 머문다.
- **카드(뒷면)**: 같은 카드 안에서 아래로 펼친다. 단어(40px로 줄임) + 발음 버튼 → IPA → 구분선 → 용례마다 **문맥 뜻**(22px 고딕 굵게) → **원문 문장**(18px 세리프, 형광펜) → 출처("— *논문 제목*", 기울임). 용례가 둘이면 점선으로 나누고, 두 번째는 한 단계 작게.
- **답 버튼**: 모름 `1` / 애매 `2` / 앎 `3`. 세 칸 균등, 높이 64px, 각각 again·hard·good의 옅은 바탕과 진한 글자. 원색을 꽉 채우지 않아 수백 번 눌러도 눈이 덜 피곤하다. 버튼 안에 "다시 보기 / 곧 다시 / 나중에"를 작게 쓴다. 실제 다음 복습일을 보여 주는 것은 9장 제안 3.
- **단축키**: `Space`/`Enter` 뒷면 보기, `1` `2` `3` 응답, `P` 발음 듣기. 저장 중에는 입력을 무시한다(기존 `locked` ref와 같은 규칙).
- **뜻 실패 카드**(5-1): 뜻 자리에 "– – 문맥 뜻을 만들지 못했습니다"(회색). 원문 문장은 그대로 크게 보여서, 뜻이 없어도 문맥으로 복습할 수 있다.
- **완료 화면**: "오늘 복습을 마쳤습니다", 카드 수·응답 수·모름 수, **홈으로** `Enter`.
- **오류**: 응답 저장 실패는 답 버튼 아래 한 줄(`again` 색 글자, 바탕 칠 없음).

### 5.6 M4에서 추가될 화면 (목업 6)

- **설정 `/settings`**: 라벨 열(이름 + 설명 회색 13px) 200px과 입력 열의 2열 행. 항목은 흔한 단어 제외 기준 N, 하루 새 카드 상한, (제안) 화면 테마. 아래에 저장 버튼.
- **카드 삭제 확인**: 400px `<dialog>`. 제목 "카드를 삭제할까요?", 본문에 단어(세리프)와 지워지는 범위, [취소 `Esc`] [삭제(danger)].
- **뜻 수정·재시도**: 5.4의 `MeaningCell` 상태로 처리한다. 새 화면은 필요 없다.

## 6. 키보드 단축키 정리

| 화면 | 키 | 동작 |
|---|---|---|
| 홈 | `Enter` | 복습 시작(카드가 있을 때) |
| 검토 | `J` `K` / `↓` `↑` | 포커스 행 이동 |
| 검토 | `Space` / `X` | 포커스 행 체크 전환 |
| 검토 | `Ctrl+Enter` | 저장 |
| 복습 | `Space` / `Enter` | 뒷면 보기 |
| 복습 | `1` `2` `3` | 모름 / 애매 / 앎 |
| 복습 | `P` | 발음 듣기 |
| 복습 완료 | `Enter` | 홈으로 |
| 단어 목록(M4) | `Enter` / `Esc` | 뜻 수정 저장 / 취소 |
| 대화상자(M4) | `Esc` | 닫기 |

입력칸에 포커스가 있을 때는 한 글자 단축키를 끈다. 화면에 보이는 버튼에는 해당 키를 `Kbd`로 붙여서 따로 외우지 않아도 되게 한다.

## 7. 상태 표시 규칙

뜻 실패, 발음기호 없음, 처리 중은 지금 흔한 상태라서 경고처럼 보이지 않게 하면서도 분명히 보이게 정했다.

| 상태 | 표시 | 색 |
|---|---|---|
| 처리 중(문서) | 회전 고리 + "뜻 채우는 중" | accent |
| 검토 대기 | 점 + "검토 대기" | accent |
| 완료 | 점 + "완료" | good |
| 오류(문서) | 점 + "오류", 제목 아래 사유 | again은 점에만 |
| 뜻 생성 중 | 회전 고리 + "뜻 만드는 중" | muted |
| 뜻 실패 | 짧은 점선 + "생성 실패" + 다시 시도 링크(M4) | 점선만 again, 글자는 muted |
| 발음기호 없음 | IPA 자리에 "발음기호 없음" | faint |
| 화면 단위 안내(API 키 없음 등) | `Notice`: 왼쪽 색 줄 + 면 바탕 한 줄 | 줄만 hard |

원칙은 하나다. **빨강·노랑은 점과 선에만 쓰고, 넓은 면을 칠하지 않는다.** 예외는 복습 답 버튼의 옅은 바탕뿐이다.

## 8. 접근성과 품질 기준

- 본문 대비 4.5:1 이상. 실측값은 다음과 같다.
  - muted 4.9:1, accent 6.6:1, 주 버튼 글자 6.9:1.
  - 답 버튼(진한 글자/옅은 바탕): 모름 4.8:1, 애매 5.2:1, 앎 4.8:1. 다크에서는 5.6~7.1:1.
  - faint(3.6:1)는 해제한 행이나 "발음기호 없음"처럼 일부러 한 단계 내린 정보에만 쓴다. 해제한 행도 다시 읽고 체크할 수 있어야 하므로 3:1 아래로는 내리지 않는다.
- 색만으로 뜻을 전하지 않는다. 상태에는 항상 글자가 붙고, 배지는 모양(칠함/점선)으로도 구분된다.
- `:focus-visible` 링, 키보드만으로 모든 조작 가능, 체크박스는 기존 `aria-label` 유지.
- 저장 중·처리 중 상태 변화는 `aria-live="polite"`, 오류는 기존 `role="alert"`를 유지한다.
- PC 전용이지만 900px 이하에서도 깨지지 않게 한다(2열을 1열로, 표는 가로 스크롤).

목업에 일부 그려 두었지만 데이터나 동작이 바뀌는 항목이다. 우선순위 순으로 적었다.

1. **홈·문서 목록에 단어 수와 뜻 실패 수 표시, 안내 줄**: 문서별 실패 수 쿼리가 필요하다. 상단 메뉴 "복습" 옆의 오늘 남은 수 배지도 레이아웃에서 쿼리가 필요하다.
2. **검토 필터 칩**(전체 / 이미 학습 중 / 사전에 없음 / 해제함)과 **Shift+클릭 범위 선택**: 클라이언트 상태만으로 가능하다. 200개 훑기 시간이 크게 준다.
3. **답 버튼에 다음 복습 간격 표시**(예: "10분 / 1일 / 3일"): `ts-fsrs`의 미리보기 결과를 카드와 함께 내려 줘야 한다. 사용자가 응답의 결과를 알고 고를 수 있다.
4. **앞면 문맥 힌트 옵션**: 앞면에 원문 문장을 단어만 가린 채 보여 주는 설정. 문맥 학습 효과는 커지지만 난이도가 바뀌므로 사용자 결정이 필요하다.
5. **뒷면을 열 때 발음 자동 재생** 설정.
6. **직전 응답 되돌리기**(`Z`): 실수로 누른 경우를 위한 것. 서버에 이전 상태를 보관해야 한다.
7. **화면 테마 설정**(시스템/라이트/다크): 토큰은 이미 `data-theme`를 받게 해 두었다.
8. 완료 화면의 모름 수: 클라이언트에서 세면 된다. 아주 작은 변경이다.
9. 예상 소요 시간("약 15분", 홈 목업): 카드당 평균 시간을 재야 한다. 우선순위는 낮다.

## 10. 구현 순서 제안 (Developer 계획용 초안)

1. 토큰과 글꼴: `globals.css` 변수·`@theme`, `next/font`(Pretendard 로컬, Gentium Google + greek). IPA 확인용으로 `/study`에서 `ˈ ˌ ə ʃ θ ð ŋ ɚ`가 한 글꼴로 나오는지 본다.
2. 부품: `src/components/ui/`의 Button, Kbd, Tag, Status, Notice, 표 스타일.
3. 레이아웃과 내비게이션(현재 위치 표시).
4. 복습 화면(단축키 포함) → 검토 화면(단축키, 저장 중 상태) → 문서 단어 목록 → 문서 목록 → 홈 순서. 오래 쓰는 화면부터.

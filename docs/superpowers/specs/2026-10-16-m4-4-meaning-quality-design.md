# M4-4 설계: 문맥 뜻 품질(사고 단계·묶음 크기·동시 요청)

- 상태: 설계(2026-10-16). 실측을 마치고 사용자와 방향을 합의했다.
- 상위 설계서: `2026-10-13-slave-voca-design.md` 8.4(문맥 뜻 생성), 11장 M4, 12장(뜻 품질 개선 검토, 뜻 묶음 동시 요청)

## 1. 문제

사용자가 꼽은 불편(2026-10-16):

1. **회차마다 뜻이 바뀐다.** 같은 단어가 같은 의미로 쓰였는데도 문서마다 다른 말로 나온다(robust: 견고한 → 강건한 → 건강한). 복습 카드 뒷면에 용례 2개가 나란히 나오므로 바로 보인다.
2. **문맥에 틀린 뜻이 나온다.** 예: progression("geometric progression")을 "진행", compelling을 "필수적인"이나 깨진 조각 "력있는", textual entailment를 "텍스트 entailment"(영어가 그대로 남음)로 답했다.

일관성은 "같은 단어가 같은 의미로 쓰였으면 같은 용어"로 정의한다. "다시 만들기"는 틀린 뜻을 바꾸려고 누르는 기능이므로 거기서는 다른 답이 나올 수 있어야 한다.

## 2. 실측(2026-10-16)

### 2.1 방법

- 앱과 같은 모델(`gemini-3.5-flash-lite`), 같은 지시(B1), 같은 재시도·깨진 글자 검사를 쓰고 설정만 바꿨다.
- 정확도: attention 논문 저장분 211개를 보내고 44개를 채점했다. 44개는 지난 B1 실험에서 실험 전에 정한 고정 40개에 문제 단어 4개(hurt, float, progression, traverse)를 더한 것이다. 맞음·애매 키워드로 자동 판정하고, 판정하지 못한 21개는 원문 문장을 보고 직접 판정했다.
- 일관성: 같은 조건을 여러 번 돌려 두 회차의 뜻이 글자까지 같은 비율(211개 전체)을 쟀다.
- 다른 논문 확인: ResNet(206개), BERT(192개)에서 지금 설정과 추천 설정을 2회씩 비교했다.
- 비용은 응답의 토큰 수(입력, 출력 + 사고)로 계산했다. 실측 전체에 약 $0.45를 썼다.

### 2.2 결과(attention, 조건별 3회)

| 조건 | 맞음 / 44 | 두 회차 같은 뜻 | 시간 | 논문 1편 비용 |
|---|---|---|---|---|
| 지금 설정(MINIMAL, 200개, 순서대로) | 42.3 | 74% | 9초 | $0.015 |
| LOW, 200개 | 41.7 | 68% | 7.5초 | $0.012 |
| MINIMAL, 50개 동시 | 42.7 | 78% | 3.8초 | $0.016 |
| **LOW, 50개 동시** | **44.0** | **81%** | **3.4초** | **$0.013** |
| 지금 설정 3회 생성 후 다수결 | 42.5 | 86% | 11초 | $0.045 |
| seed 고정(42) | 41.0 | 100% | 11초 | $0.018 |

- **LOW·50개는 3회 모두 44개를 다 맞혔다.** 지금 설정에서 틀리던 progression("등비수열"·"수열"), compelling("성능이 뛰어난"), textual entailment("함의")를 바로잡았다. 뜻에 영어가 남거나 사전형이 아닌 활용형("허가한다")이 나온 경우도 0개였다.
- **다른 논문:** 두 회차 같은 뜻은 ResNet 78% → 80%, BERT 73% → 75%로 오름폭이 작았다. 비용은 같았다(ResNet $0.013 → $0.015, BERT $0.015 → $0.013). 두 회차 모두 같은 답을 냈는데 지금 설정과 다른 뜻은 ResNet 28개, BERT 10개였다. 대부분 비슷하거나 더 나았다(aggressively "매우 깊게" → "과감하게", margins "마진" → "차이", restore "복원하는" → "복원하다").
- **남은 차이 20~25%는 대부분 오답이 아니다.** 품사 표기(신경망 / 신경망의, 계층적 / 계층적인), 음차 표기(에포크 / 에폭), 같은 뜻의 다른 말이다.

### 2.3 채택하지 않은 방법

- **seed 고정:** 같은 요청에는 늘 같은 답을 주지만 정확도는 나아지지 않았다. 문서가 다르면 문장이 달라 요청도 다르므로 문서 간 일관성에는 소용이 없다. "다시 만들기"는 같은 답만 돌려주게 된다.
- **다수결(3회 생성):** 일관성은 가장 높지만 비용이 3배이고 정확도는 LOW·50개보다 낮았다.
- **기존 뜻 참고**(다른 문서에서 만든 그 단어의 뜻을 `known`으로 함께 보내고 "의미가 같으면 같은 표현"이라고 지시): 결과가 오락가락했다. 앞 문서와 같은 뜻이 1회차에는 40 → 45/54개로 늘었지만 2회차에는 36 → 26/54개로 줄었다. 2회차에는 "구현했다", "달성한다" 같은 활용형이 한 번에 13개 나왔다.
- **temperature 낮추기:** 시험하지 않았다. Gemini 3 공식 안내가 기본값 1.0 유지를 권하고, 낮추면 반복 출력이나 품질 저하가 생길 수 있다고 한다.

## 3. 바꾸는 것

1. **사고 단계:** `thinkingLevel`을 `MINIMAL`에서 `LOW`로 바꾼다. 저장 직후 채우기와 다시 만들기 모두 같은 모델을 쓰므로 둘 다 바뀐다.
2. **묶음 크기:** `MEANING_BATCH_SIZE`를 200에서 50으로 바꾼다.
3. **동시 요청:** 묶음을 순서대로 보내지 않고 최대 5개까지 동시에 보낸다. 논문 한 편(후보 약 200개, 묶음 4~5개)이 한 번에 나간다. 동시 처리는 기존 `mapWithConcurrency`(`src/lib/async/pool.ts`)를 쓴다.
   - 재시도·깨진 글자 검사·실패 처리는 묶음마다 지금과 같다. 한 묶음이 실패해도 다른 묶음 결과는 그대로 저장한다.
   - 결과(`done`, `failedIds`) 순서는 묶음 순서를 따른다(결과가 실행 순서에 따라 달라지지 않게).
   - 로그의 묶음 번호(`묶음 N`)는 지금처럼 1부터 센다.
4. **그대로인 것:** 시스템 지시(B1), 응답 스키마, `maxOutputTokens: 16384`, 재시도 규칙, 화면, DB.
5. **주석:** 200개 묶음의 이유로 적힌 무료 등급 한도(분당 5요청)는 더 이상 근거가 아니다(유료 등급 키). 새 이유(50개 묶음이 실측에서 더 정확, 동시 5개로 속도 확보)로 바꾼다.

## 4. 위험과 대응

- **요청 한도(429):** 저장 한 번에 요청이 최대 5개 동시에 나간다. 유료 등급의 분당 한도는 이보다 훨씬 크다. 429가 나도 지금의 백오프 재시도가 처리한다.
- **큰 문서:** 후보가 1,000개면 묶음 20개를 5개씩 4번에 나눠 보낸다. 지금(200개씩 5번 순서대로)보다 느려지지 않는다.
- **비용:** 실측에서 논문 1편 $0.013~0.015로 지금과 같다. 묶음마다 지시문이 다시 들어가 입력이 조금 늘지만, LOW에서 출력이 줄어 상쇄됐다.
- **이미 저장된 뜻:** 바뀌지 않는다. 새로 올리는 문서와 다시 만들기부터 적용된다.

## 5. 확인 방법

- 단위 테스트(SDK 목):
  - 요청 설정이 `thinkingLevel: LOW`다(기존 "minimal thinking" 테스트를 바꾼다).
  - 450개를 보내면 50개 묶음 9개로 나뉘고 모든 뜻이 모인다.
  - 동시에 실행 중인 묶음이 5개를 넘지 않는다(목이 진행 중인 요청 수의 최댓값을 기록).
  - 한 묶음만 실패하면 그 묶음 id만 `failedIds`에 들어가고 나머지는 `done`이다.
  - 묶음이 늦게 끝나는 순서와 상관없이 결과 순서는 묶음 순서다.
  - 재시도·깨진 글자 테스트는 그대로 통과한다.
- 실제 API(1회, 약 $0.015): attention 논문을 앱에서 올려 실패 0, 걸린 시간(약 4초 안팎)을 확인한다. 위 채점 도구로 44개를 채점해 맞음 43개 이상인지 본다.
- 실측 스크립트와 결과: PM 스크래치(`scratchpad/exp`). 저장소에는 넣지 않는다.

## 6. 범위 밖

- 품사·음차 표기 흔들림(신경망 / 신경망의, 에포크 / 에폭) 통일. 비용이 더 드는 방법(다수결, 사후 정규화)이 필요하다.
- 기존 뜻 참고 방식의 재설계.
- 더 큰 모델로 교체(`gemini-3.6-flash`는 2026-10-16 실측에서 503 과부하).

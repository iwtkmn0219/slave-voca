# M6-1 화면 규칙: 로그인, 승인 대기, 사용 중지, 관리, 계정 메뉴

- 작성: Designer, 2026-10-16. 요청: PM(M6-1, v0.6.0 비공개 베타).
- 목업: `docs/superpowers/mockups/m6-1-auth.html` (주소 끝 `#light` / `#dark`로 테마 고정)
- 바탕: UI 개편안 `2026-10-15-ui-redesign.md`(A안 「지면」) 3장 토큰, 4장 부품, 7장 상태 규칙. 이 문서에 없는 것은 개편안을 따른다.
- 범위: 화면 모양과 문구. 인증 방식, 세션, DB 상태 이름은 PM 설계서가 정한다.

## 0. 원칙

1. **처음 온 사람에게는 설명 대신 카드 한 장을 보여 준다.** 초대 링크로 온 사람은 앱이 무엇인지 모른다. 이 앱이 만드는 결과물(단어, 발음기호, 문맥 뜻, 형광펜 문장)을 보여 주면 한 문장으로 설명할 수 있다.
2. **인증 화면 세 개(로그인, 승인 대기, 사용 중지)는 같은 틀을 쓴다.** 상단 바 없이 가운데 한 열에 둔다. 앱 안으로 들어가는 길이 없는 상태이므로 메뉴를 보여 주지 않는다.
3. **지인끼리 쓰는 베타라서 어조는 담담하게.** 합니다체로 쓰고, 탓하거나 겁주는 말("차단", "거부", "권한 없음")은 쓰지 않는다. 화면에서는 "차단"을 **"사용 중지"**라고 쓴다. 데이터의 상태 이름(`blocked` 등)은 그대로 둔다.
4. **빨강은 점과 선에만 쓴다**(개편안 7장 그대로).

| 항목 | 값 |

| 테마 | 라이트: 바탕 `#FFFFFF`, 1px 안쪽 테두리 `#747775`, 글자 `#1F1F1F`. 다크: 바탕 `#131314`, 테두리 `#8E918F`, 글자 `#E3E3E3`. 새 토큰 `--g-fill` / `--g-stroke` / `--g-text`를 `light-dark()`로 하나씩 둔다. 앱 토큰(accent 등)을 섞지 않는다 |
| 크기 | 높이 40px, 폭은 열 전체(400px 이하). 모서리 4px(가이드의 rectangular 모양) |
| 안쪽 여백 | 로고 왼쪽 12px, 로고 뒤 10px, 글자 오른쪽 12px |
| 로고 | 20×20, 버튼 왼쪽 12px에 고정하고 글자는 버튼 가운데에 둔다(GIS 넓은 버튼과 같은 배치). **Google 브랜드 자료 묶음의 표준 색 "G" 파일을 고치지 않고 쓴다.** 단색으로 바꾸거나 색을 바꾸지 않고, 직접 그리지 않는다. 목업의 G는 자리표시다 |

| 요소 | `<button>`(폼 POST든 클라이언트 호출이든). 링크로 만들 때도 버튼 모양이 같아야 한다 |

### 2.3 실패로 돌아올 때

버튼 바로 위 12px에 한 줄을 둔다. 버튼 자체가 다시 시도이므로 "다시 시도" 링크는 따로 두지 않는다.

| 경우 | 모양 | 문구 | 역할 |
|---|---|---|---|
| 취소(사용자가 Google 화면에서 그만둠) | `Notice` 모양에 왼쪽 줄 색만 line-strong(경고가 아님) | "로그인을 취소했습니다. 계속하려면 아래 버튼을 다시 눌러 주세요." | `role="status"` |
| 그 밖의 모든 실패 | `Notice` 모양에 왼쪽 줄 again | "로그인하지 못했습니다. 잠시 뒤 다시 시도해 주세요." | `role="alert"` |

- 원인 코드(OAuth 오류 이름)는 화면에 보이지 않는다. 콘솔이나 서버 로그에만 남긴다.
- 안내는 주소의 쿼리(예: `?error=…`)로 받는다. 버튼을 다시 누르면 사라진다. 새로 고침하면 남아 있어도 괜찮다.
- `Notice` 부품에 `tone` 변형("neutral" = line-strong, "error" = again, 기본 = hard)을 더하면 된다.

### 2.4 로그인한 뒤(PM 결정 2026-10-16)

- 결정: 넣는다. 로그인하지 않은 채 앱 주소로 오면 `/login?next=<원래 경로>`로 보내고, 로그인하면 그 경로로 돌아간다. `next`는 같은 사이트의 경로(`/`로 시작, `//`·`/\`가 아님, 인증 화면·API가 아님)만 받고 아니면 홈.


어느 주소로 왔다가 로그인 화면으로 보내졌다면, 로그인한 뒤 **원래 가려던 주소로** 돌려보내 주면 좋겠다(초대 링크가 `/documents/…`일 수도 있다). 승인 대기·사용 중지 계정은 주소와 상관없이 2·3장 화면으로 간다.

## 3. 승인 대기

### 3.1 구성

1. 작업명
2. 상태 줄: `Status` wait(accent 점) + "승인 대기". 아래 10px
3. 제목: "승인을 기다리고 있습니다"
4. 본문: "관리자가 확인하면 바로 쓸 수 있습니다. 승인이 끝나면 이 화면이 저절로 넘어가니, 나중에 이 주소로 다시 들어오면 됩니다."
5. 계정 칸(3.2), 위 24px
6. 보조 문구: "다른 계정으로 들어가려면 로그아웃한 뒤 다시 로그인하세요." 다른 Google 계정으로 잘못 들어온 경우를 위한 안내다

승인이 언제 될지 모르므로 시간을 약속하는 말("곧", "24시간 안에")은 쓰지 않는다.

### 3.2 계정 칸(승인 대기·사용 중지 공용)

- surface 바탕, line 테두리, `radius-lg`, 안쪽 12px(왼쪽 14px). 가로 한 줄: [머리글자 원 32px] [이름 / 이메일] [로그아웃]
- 머리글자 원: accent-soft 바탕, accent 글자 14px 700. 이름의 첫 글자를 대문자로 쓰고, 이름이 없으면 이메일의 첫 글자를 쓴다. **Google 프로필 사진은 쓰지 않는다**(외부 이미지 요청을 늘리지 않고, 사진이 없는 계정과 모양을 맞춘다)
- 이름: 14px 600 ink. 이메일: 13px muted. 둘 다 한 줄로 두고 넘치면 말줄임. 이름이 없으면 이메일 한 줄만 쓴다
- 로그아웃: `Button` ghost sm. 누르면 바로 로그아웃하고 `/login`으로 간다. 확인 대화상자는 띄우지 않는다

### 3.3 저절로 넘어가기(PM 결정 2026-10-16)

- 결정: 넣는다. 탭이 다시 보일 때 한 번 다시 확인하고, 승인됐으면 **홈으로** 간다(서버가 대기 화면에서 원래 주소를 알 수 없다). 본문은 "승인이 끝나면 이 화면이 저절로 넘어가니…" 쪽을 쓴다.


본문의 "이 화면이 저절로 넘어가니"는 이 동작을 전제로 한다. 탭이 다시 보일 때(`visibilitychange`, `focus`) 상태를 한 번 다시 확인하고, 승인됐으면 원래 주소로 보낸다. 주기적인 폴링은 하지 않는다. 이 동작을 넣지 않기로 하면 본문을 "승인이 끝난 뒤 이 주소로 다시 들어오면 바로 시작할 수 있습니다."로 바꾼다.

## 4. 사용 중지(차단된 계정)

- 3장과 같은 틀. 상태 줄은 `Status` idle(faint 점) + "사용 중지됨". 빨간 점은 쓰지 않는다. 경고가 아니라 상태를 알리는 화면이다
- 제목: "이 계정으로는 쓸 수 없습니다"
- 본문: "관리자가 이 계정의 사용을 멈췄습니다. 잘못된 것 같다면 초대해 준 분께 알려 주세요."
- 계정 칸(3.2). 보조 문구는 없다
- 관리자 연락처는 보여 주지 않는다. 초대 기반이라 초대한 사람을 이미 안다

## 5. 상단 바

### 5.1 배치

```
slave-voca  홈  복습 19  문서                [관리 2]  설정  │  (김) 김연구 ⌄
```

- 왼쪽은 지금 그대로다. 오른쪽 끝 묶음은 [관리(관리자만)] · 설정 · 구분선(1px × 20px, line, 좌우 8px) · 계정 버튼 순서다. "관리"가 `ml-auto`를 가진다. 관리자가 아니면 설정이 `ml-auto`를 가진다
- **관리**: 다른 메뉴와 같은 링크 모양. 현재 위치(`/admin…`)이면 sunken 바탕 + 굵게. 대기 중인 사람이 있으면 복습 배지와 같은 모양으로 숫자를 둔다(12px 600 accent `tabular-nums`). 0이면 숫자를 숨긴다. 관리자가 아니면 메뉴 자체를 그리지 않는다
- 배지 숫자는 승인·사용 중지 처리 뒤에 다시 그린다(되돌리기 뒤 복습 배지와 같은 방식)

### 5.2 계정 버튼과 팝오버

- 버튼: 머리글자 원 24px(12px 700) + 이름(14px ink-2, 최대 140px, 말줄임) + 아래 화살표 14px(muted). 안쪽 4px 8px 4px 4px, `radius-md`. 마우스 올림과 열림 상태에서 sunken 바탕. 이름이 없으면 이메일의 @ 앞부분을 쓴다
- 640px 아래(모바일 전체 개편 전 임시)에서는 이름을 숨기고 원과 화살표만 둔다. 이때 `aria-label="계정: 이름"`
- 누르면 팝오버가 열린다. **네이티브 `popover` 속성 + `popovertarget`**으로 만든다. Esc와 바깥 클릭으로 닫히고, 닫히면 포커스가 버튼으로 돌아온다. JS 없이 이 동작을 다 얻는다
  - 위치: 상단 바 오른쪽 아래 고정(`position: fixed; top: 48px; right: 16px`). 버튼이 늘 오른쪽 끝에 있으므로 anchor positioning이 필요 없다
  - 260px, surface, line 테두리, `radius-lg`, `shadow-2`, 안쪽 6px
  - 머리: 이름 14px 600 / 이메일 13px muted(`overflow-wrap: anywhere`), 아래 line 구분선. 승인 대기 화면처럼 "어느 Google 계정으로 들어왔는지"를 여기서 확인한다
  - 항목: "로그아웃" 한 줄(14px ink, 7px 10px, 마우스를 올리면 sunken). 확인 없이 바로 로그아웃
  - `role="menu"`는 쓰지 않는다(화살표 키 이동을 구현하지 않으므로). 팝오버 안의 버튼을 Tab으로 오가는 일반 대화형 영역이다. 버튼에는 `aria-expanded`를 둔다
- 관리 화면 링크는 팝오버에 넣지 않는다. 상단 바에 이미 있고, 배지가 보여야 하기 때문이다

| 칸 | 내용 |
|---|---|
| 사용자 | 이름 14px 600 / 이메일 13px muted(`overflow-wrap: anywhere`). 이름이 없으면 이메일만 굵게. 관리자 자신의 행에는 이름 뒤에 테두리 배지 "나"(Tag의 nodict처럼 테두리만 두되 실선, muted) |
| 상태 | `Status`. 대기 = wait "승인 대기", 승인 = ok "승인됨", 사용 중지 = idle(faint 점) "사용 중지", 관리자 = ok "관리자" |
| 가입 | "10월 16일 14:32"(`ko-KR`, month long, day, 24시간 hour:minute). 올해가 아니면 앞에 "2025년". 13px ink-2 `tabular-nums` |

### 6.3 정렬

- 대기 중인 사람을 위에, **가입이 오래된 순**(오래 기다린 사람부터)으로 둔다. 그 아래는 승인·관리자·사용 중지를 가입 최신 순으로 섞어 둔다(상태 칸이 구분해 준다)
- 대기 묶음과 나머지 사이에 2px line-strong 구분선을 하나 둔다. 대기가 없으면 구분선도 없다
- **처리한 뒤에도 행은 그 자리에 둔다.** 승인한 사람이 바로 아래로 뛰어내려가면 눈이 따라가지 못하고, 연달아 누르다가 다른 사람을 누르게 된다. 다음에 화면을 열 때 다시 정렬한다

### 6.4 처리 중 · 결과

- 확인 대화상자는 띄우지 않는다. 모든 동작은 반대 동작으로 되돌릴 수 있다(사용 중지 ↔ 다시 허용). 승인을 되돌리는 동작은 "사용 중지"이다
- 처리 중: 그 행의 버튼 전부 `disabled`, 상태 칸은 `Status` busy "바꾸는 중". 다른 행은 그대로 쓸 수 있다
- 성공: 상태 칸과 동작 버튼이 새 상태로 바뀐다. 따로 성공 문구는 띄우지 않고, 화면 읽기 프로그램에만 `aria-live="polite"`로 "김연구 님을 승인했습니다" / "…의 사용을 멈췄습니다" / "…를 다시 허용했습니다"를 알린다. 상단 바 "관리" 배지와 요약 줄을 다시 그린다
- 실패: 상태 칸은 원래 상태로 두고, 그 아래 줄에 `Failed` "바꾸지 못했습니다"(`role="alert"`)를 둔다. 버튼은 다시 쓸 수 있다(누르면 다시 시도). 그 행에서 다음 동작이 성공하면 문구가 사라진다
- 관리자 자신을 사용 중지하는 요청은 서버에서도 거부한다(화면에 버튼이 없어도). 거부되면 실패와 같은 표시를 쓴다

### 6.5 키보드

- Tab으로 행의 버튼을 차례로 오간다. 검토 표 같은 행 포커스나 단축키는 두지 않는다(사람이 10명 안팎이고 가끔 쓰는 화면이다)
- 처리 중 버튼이 `disabled`가 되어도 포커스를 잃지 않게, 누른 버튼에 포커스를 둔 채 `aria-disabled`로 막는 편이 낫다. 처리가 끝나 버튼 모양이 바뀌면(승인 → 사용 중지) 그 행의 첫 버튼으로 포커스를 옮긴다

## 9. 확인 기준(검수 때 볼 것)

- 1280 / 375 / 320px에서 로그인·승인 대기·사용 중지 화면에 가로 스크롤이 없고, 375px에서 Google 버튼이 첫 화면(667px 높이)에 들어온다
- 라이트·다크·시스템 세 모드에서 Google 버튼 색이 2.2 표와 같다(바탕, 테두리, 글자). G 로고 색이 바뀌지 않는다
- 로그인 실패 두 종류의 줄 색과 역할(status / alert)
- 관리: 처리 뒤 행이 움직이지 않음, 배지와 요약 갱신, 자기 행에 버튼 없음, 실패 문구 위치
- 계정 팝오버: Esc·바깥 클릭으로 닫히고 포커스가 버튼으로 돌아옴. 640px 아래에서 이름 숨김
- 글자에 faint를 쓰지 않음(점에만)

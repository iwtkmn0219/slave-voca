## 3. C-1 사용량·비용·알림

### 3.1 비용이 생기는 곳

Gemini는 PDF를 올릴 때가 아니라 **뜻을 만들 때** 부른다. 입구는 세 곳이다.

| 입구 | 코드 | 출처 이름 |
|---|---|---|
| 검토 화면 저장 | `review/actions.ts` → `enrichDocument` | `save` |
| 문서의 뜻 다시 만들기(단어 하나, 여러 개, 모두 다시 시도) | `documents/[id]/actions.ts` → `regenerateMeanings` | `regenerate` |
| 복습 카드 뒷면의 다시 만들기 | `/api/usage-meaning` → `regenerateUsageMeaning` | `card` |

- PDF 올리기와 후보 보기는 한도와 상관없이 된다.
- 이미 만든 카드의 복습은 언제나 된다.

### 3.2 기록

새 표 `meaning_usage`에 **뜻 만들기 요청 한 번(위 입구 한 번)마다 한 줄**을 남긴다.

| 열 | 뜻 |
|---|---|
| `id` | 기본 키 |
| `user_id` | 요청한 사용자. users 외래 키, **사용자를 지우면 NULL**(비용 기록은 남아 전체 상한 계산이 줄지 않는다) |
| `source` | `save` / `regenerate` / `card` |
| `words` | 요청한 단어(용례) 수. 재시도는 다시 세지 않는다 |
| `input_tokens`, `output_tokens` | Gemini 응답 `usageMetadata`의 합. 재시도와 실패한 묶음까지 받은 응답은 모두 더한다. 사고 토큰은 출력에 포함된다 |
| `cost_usd` | 아래 단가로 계산한 실제 비용. 끝나기 전에는 예상 비용 |
| `settled` | 실제 비용으로 바뀌었는지 |
| `created_at` | 요청 시각 |

- **단가:** Gemini 3.5 Flash-Lite 표준 유료 요금. 입력 100만 토큰당 $0.30, 출력 $2.50(사고 포함)이다. 2026-10-17에 공식 요금표(ai.google.dev/gemini-api/docs/pricing)로 확인했다. 코드에 상수로 두고 확인한 날짜를 주석에 적는다.
- **예상 비용:** 단어당 $0.0001로 잡는다(보수적으로).
  - M4-4 실측에서 논문 한 편(단어 211개)에 입력 약 11,500토큰, 출력 약 4,000토큰이 들었다.
  - 단어당으로 바꾸면 약 $0.000064다.
- **실측 비용이 계속 남는다:** 모델 호출이 돌려주는 사용량을 기록까지 이어야 한다. 지금 `MeaningModel`은 뜻만 돌려준다. 그래서 사용량도 함께 돌려주도록 바꾼다(정확한 형태는 계획서에서 정한다).

### 3.3 한도 확인

- **한 달:** 한국 시간 매월 1일 0시부터 다음 달 1일 0시 전까지다.
- **한도 값:** 환경변수로 바꿀 수 있다. `MONTHLY_WORD_LIMIT`(기본 4000), `GEMINI_MONTHLY_BUDGET_USD`(기본 5). 관리자도 같은 한도를 따른다.
- **확인 순서:** Gemini를 부르기 전에 한 트랜잭션 안에서 다음을 한다.
  1. **개인:** 그 사용자의 이번 달 `words` 합 + 이번 요청 단어 수 ≤ 개인 한도
  2. **전체:** 이번 달 `cost_usd` 합(끝나지 않은 줄은 예상 비용) + 이번 요청 예상 비용 ≤ 전체 상한
  3. 통과하면 예상 비용으로 줄을 먼저 쓴다(**맡아 두기**). Gemini 호출이 끝나면 실제 토큰과 비용으로 바꾸고 `settled`를 켠다.
- **맡아 두는 이유:** 두 창에서 동시에 저장해도 한도를 넘지 않게 한다. better-sqlite3는 동기식이라 확인과 기록이 한 트랜잭션에 들어간다.
- **호출 중 예외로 끝나도** 받은 응답의 토큰까지는 기록한다. 하나도 못 받았으면 비용은 0이고, 단어 수는 그대로 센다.
- **막혔을 때:**
  - 검토 저장: 아무것도 저장하지 않는다. 카드, 용례, 아는 단어 모두 그대로다.
  - 다시 만들기: 원래 뜻을 그대로 둔다.
  - 두 경우 모두 이유를 알린다(3.4).
  - 개인 한도와 전체 상한은 사용자에게 같은 내용으로 알린다.
- **API 키가 없을 때:** 지금처럼 뜻을 failed로 둔다. 이때는 비용이 없으므로 한도를 확인하지 않는다.

### 3.4 화면에 필요한 내용(구성은 Designer가 정한다)

- **한도에 걸렸을 때(사용자):**
  - 알릴 내용: 이번 달 사용량을 다 써서 뜻을 만들 수 없다는 것, 관리자에게 문의하면 된다는 것
  - 이 안내가 나오는 곳: 검토 화면 저장, 문서의 다시 만들기, 복습 카드의 다시 만들기
  - 사용자에게 남은 양이나 사용량은 보이지 않는다.
  - (2026-10-17 Designer 규칙 반영) 다시 쓸 수 있는 날(한국 시간 다음 달 1일, 예: "11월 1일")은 알린다. 날짜만이라 사용량은 드러나지 않는다. 문구는 `2026-10-17-c-screens.md` 2장.
- **관리 화면(관리자만):**
  - 사용자별 이번 달 사용 단어 수
  - 이번 달 전체 Gemini 비용과 상한
  - 위 두 값의 한 달은 한국 시간 기준이다.

### 3.5 알림

`ALERT_WEBHOOK_URL`이 있으면 웹훅으로 보낸다. 없으면 서버 로그에만 남긴다.

| 알림 | 언제 | 같은 알림을 다시 보내는 조건 |
|---|---|---|
| 서버 오류 | 처리하지 못한 요청 오류(Next `onRequestError`, `instrumentation.ts`), 뜻 채우기가 예외로 끝나 문서가 error가 됐을 때 | 같은 오류는 10분에 한 번 |
| 비용 | 이번 달 전체 비용이 상한의 80%, 100%에 닿았을 때 | 각각 한 달에 한 번 |
| 한도 도달 | 어떤 사용자가 개인 한도에 걸렸을 때(이름, 이메일). 전체 상한 때문에 막혔을 때도 따로 한 번 | 사용자마다 한 달에 한 번, 전체 상한은 한 달에 한 번 |
| 가입 신청 | 새 계정이 승인 대기로 만들어졌을 때(이름, 이메일, 관리 화면 주소). Better Auth `databaseHooks.user.create.after` | 매번 |

- **형식:** 주소의 호스트가 `discord.com`·`discordapp.com`이면 `{ content }`, `hooks.slack.com`이면 `{ text }`로 보낸다. 그 밖의 주소는 보내지 않고 로그에 남긴다.
- **알림에 넣지 않는 것:** 문서 문장, 뜻, 비밀값, 세션 정보
- **서버 오류 알림 내용(C-1 리뷰 반영):** 오류 종류(name), code, status만 보낸다. 메시지는 값(문장·키)을 담을 수 있어 서버 로그에만 남긴다.
- **보내기 실패:** 앱 동작을 막지 않는다. 5초 안에 끝나지 않으면 포기하고 로그에 남긴다.
- **"한 달에 한 번" 기록:** DB에 남겨 서버가 다시 시작해도 다시 보내지 않는다. 10분 조건은 메모리에 둔다.

### 3.6 확인

- **단위 테스트:**
  - 한 달 경계(한국 시간 1일 0시 직전·직후)
  - 개인 한도와 전체 상한이 각각 걸리는지
  - 맡아 두기: 확인 직후 다른 요청이 같은 한도를 넘지 못하는지
  - 세 입구가 모두 확인하는지, 막혔을 때 아무것도 바뀌지 않는지
  - 재시도가 단어 수를 다시 세지 않는지
  - 실제 토큰으로 정산되는지
  - 사용자를 지워도 비용이 남는지
  - 웹훅 형식 구분과 다시 보내는 조건
- **헤드리스 브라우저:** 한도를 작게 둔 환경(`MONTHLY_WORD_LIMIT=5`)에서 저장과 다시 만들기가 막히는 안내, 관리 화면의 사용량
- **실제 Gemini 한 번:** 논문 하나를 저장해 기록된 토큰과 비용이 위 실측과 비슷한지 본다.

## 4. C-3 휴대폰 복습 화면

화면 구성(배치, 크기, 스크롤, 무엇을 보이고 숨길지)은 Designer가 정한다. 이 절은 화면에 필요한 내용과 기술 조건만 적는다.

### 4.1 복습 화면에 필요한 내용

- **앞면:** 단어
- **뒷면:**
  - 뜻, 발음기호
  - 용례 목록(문장, 그 용례의 문맥 뜻, 출처 문서)
- **사용자가 할 수 있는 일:**
  - 뒷면 보기
  - 발음 듣기
  - "모름 / 애매 / 앎"으로 답하기
  - 직전 응답 되돌리기(되돌릴 단어와 응답이 보인다)
  - 용례 뜻 다시 만들기(진행 중·실패 상태 포함, 한도 안내 3.4)
- **상태:**
  - 복습할 카드가 없음
  - 오늘 복습을 다 마침
  - 저장 중
  - 저장 실패
- **쓰는 상황:** 지하철이나 이동 중에 휴대폰으로 짧게 복습한다. 키보드는 없다.

### 4.2 기술 조건

- **대상:** 폭 360~430px 세로, iOS Safari와 Android Chrome
- **PC 동작:** PC에서는 키보드 단축키가 지금처럼 동작해야 한다.
- **iOS 소리 제약:** iOS는 사용자가 누르기 전에는 소리를 막을 수 있다. 그래서 자동 발음이 안 될 수 있다.

### 4.3 나머지 화면

- **대상:** 홈, 로그인·승인 대기·사용 중지, 설정, 문서 목록·상세, 관리, 업로드·검토
- **요구:** 폭 360px에서 가로 스크롤 없이 쓸 수 있으면 된다. 휴대폰에 맞춰 다듬는 대상은 복습 화면뿐이다.

### 4.4 진행과 확인

- **진행:**
  1. Designer가 위 내용으로 휴대폰 복습 화면 규칙과 목업을 만든다.
  2. PM이 규칙을 받아 계획서를 쓴다.
  3. Developer가 구현한다.
- **확인:**
  - 헤드리스 브라우저를 360×740, 390×844 크기로 띄워 확인한다.
  - 실제 휴대폰 확인은 C-2 배포 뒤 사용자 폰으로 한 번 한다.

## 5. C-2 배포 묶음

### 5.1 이미지

- **독립 실행 빌드:** `next.config.ts`에 `output: 'standalone'`을 켠다.
- **Dockerfile(여러 단계):**
  - 빌드 단계: Node 24 slim에서 `npm ci` → `next build`
  - 실행 단계:
    - 독립 실행 빌드 결과와 `.next/static`, `public`을 복사한다.
    - 런타임에 읽는 파일 `data/`(빈도표, CMUdict, NOTICE)와 `drizzle/`(마이그레이션)도 복사한다. 독립 실행 빌드가 이 파일을 챙기지 못할 수 있어 직접 넣는다.
    - Litestream 실행 파일을 넣는다.
  - better-sqlite3는 네이티브 모듈이므로 빌드 단계와 실행 단계의 OS 이미지를 맞춘다.
- **프로토타입에서 확인할 것:** 독립 실행 빌드에서 pdfjs-dist(`serverExternalPackages`)가 동작하는지

### 5.2 DB와 백업

- **DB 위치:** Fly 볼륨 `/data`(1GB)에 두고 `SLAVE_VOCA_DB=/data/app.db`로 가리킨다.
- **WAL:** `client.ts`에서 `journal_mode=WAL`과 `busy_timeout`을 켠다. 로컬도 같다. Litestream은 WAL에서만 동작한다.
- **시작 순서:**
  1. 볼륨에 DB가 없고 R2에 복제본이 있으면 먼저 되살린다(`litestream restore -if-db-not-exists -if-replica-exists`).
  2. `litestream replicate -exec "node server.js"`로 앱과 복제를 함께 띄운다. 앱이 끝나면 복제도 끝나고, Fly가 다시 띄운다.
- **R2:** 버킷 하나, 그 버킷에만 쓸 수 있는 API 토큰. 접근 키는 Fly 비밀값으로 넣는다.
- **Fly 볼륨 스냅샷:** 기본 일일 스냅샷을 켜 둔다.
- **되살리기 연습:** 지인을 초대하기 **전에** 실제로 한 번 해 본다. R2에서 로컬 파일로 되살려 문서·카드 수가 서버와 같은지 본다. 결과를 `docs/superpowers/notes/`에 남긴다.

### 5.3 Fly 설정(`fly.toml`)

- **리전과 대수:** 도쿄(`nrt`), 머신 1대, **항상 켜 둔다**(`min_machines_running = 1`, 자동 정지 끔). 꺼졌다 켜지면 첫 요청이 늦고 복제도 멈춘다.
- **크기:** 처음 안은 shared-cpu-1x 512MB다.
  - 프로토타입에서 50MB PDF 처리 중 메모리를 재고, 모자라면 1GB로 정한다.
  - 월 비용은 512MB 약 $3.5, 1GB 약 $6이다. 정확한 값은 C-2에서 Fly 요금표로 확인한다.
- **연결:** HTTPS 강제, 내부 포트는 앱 포트
- **상태 확인:** `/api/health`가 DB에 `select 1`을 해 보고 200으로 답한다. Fly의 HTTP 확인이 이 주소를 본다. 로그인 없이 답한다(proxy.ts는 이미 API를 제외한다).
- **비밀값(`fly secrets`):**
  - `GEMINI_API_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `ADMIN_EMAILS`, `ALERT_WEBHOOK_URL`, R2 접근 키와 버킷 정보
  - `BETTER_AUTH_SECRET`: 로컬과 **다른 값**을 새로 만든다.
  - `BETTER_AUTH_URL`: 배포 주소(`https://…fly.dev`)
- **넣지 않는 값:** `AUTH_DEV_LOGIN`. 넣어도 localhost가 아니면 켜지지 않는다.
- 저장소에는 비밀값을 두지 않는다.

### 5.4 배포 방법과 안내서

- **배포:** 릴리스 태그가 붙은 main을 `fly deploy`로 올린다.
  - 베타 동안은 손으로 하고, **배포할 때마다 사용자 승인**을 받는다.
  - 자동 배포(GitHub Actions)는 1.0 이후에 검토한다.
- **안내서 `docs/deploy.md`에 적을 것:**
  - 처음 설정
  - 배포
  - 로그 보기
  - 비밀값 바꾸기
  - 이전 이미지로 되돌리기
  - R2에서 되살리기
  - 볼륨 스냅샷에서 되살리기

### 5.5 사용자가 할 일

C-2 마지막에 순서표로 한 번에 안내한다. 각 단계에서 무엇을 만들고, 값을 어디에 넣는지까지 적는다.

1. **Fly.io:** 가입하고 카드를 등록한 뒤, `flyctl`을 설치하고 로그인한다.
2. **Cloudflare:** 가입하고, R2 버킷과 그 버킷 전용 API 토큰을 만든다.
3. **웹훅:** Discord(또는 Slack) 채널 웹훅을 만든다.
4. **Google Console:**
   - 배포 주소의 리디렉션 URI(`https://…fly.dev/api/auth/callback/google`)를 더한다.
   - 지인이 로그인하려면 둘 중 하나를 한다.
     - (a) 동의 화면을 "프로덕션으로 게시"한다. 기본 범위만 쓰므로 Google 검토가 필요 없다.
     - (b) 지인 Gmail을 테스트 사용자로 등록한다(최대 100명).

### 5.6 프로토타입에서 확인할 것

- 로컬 Docker로 이미지를 빌드하고 띄워 한 바퀴 돌린다: 로그인(개발 전용 로그인) → 업로드 → 저장 → 복습
- Litestream을 로컬 파일 복제 대상으로 두고 복제와 되살리기를 확인한다.
- 50MB PDF를 처리할 때 메모리를 잰다.
- 이 PC에 Docker가 없으면 사용자에게 설치를 부탁한다.

# 1부. C-1 사용량 한도 안내 · 관리 화면 사용량

## 1. 원칙

1. **고장이 아니라 "이번 달 몫을 다 쓴" 상태다.** 그래서 실패 표시(again 빨강 점선)를 쓰지 않는다. 화면 단위 안내(`Notice`)와 같은 **hard 색 실선**을 쓴다. "다시 시도" 버튼도 두지 않는다. 다시 눌러도 결과가 같기 때문이다(API 키가 없을 때와 같은 규칙).
2. **남은 양과 사용량은 보이지 않는다**(사용자 결정). 대신 **언제 다시 쓸 수 있는지**는 알린다. 날짜만 알려 주므로 사용량이 드러나지 않고, "관리자에게 문의"보다 먼저 스스로 판단할 수 있다.
3. **개인 한도와 전체 상한을 구분하지 않는다.** 문구가 하나다.
4. **원래 상태가 그대로라는 것을 함께 말한다.** 저장이 막혔으면 고른 단어가 그대로 있다는 것, 다시 만들기가 막혔으면 원래 뜻이 그대로라는 것을 알린다.

## 2. 문구

`{다음 달 1일}`은 한국 시간 기준 다음 달 1일이다. 예: "11월 1일". 12월에는 "1월 1일"이고 연도는 붙이지 않는다. 서버가 한도 결과와 함께 돌려주는 편이 맞다(한 달 계산이 서버에 있다).

| 상수 | 문구 | 쓰는 곳 |
|---|---|---|
| `LIMIT_SAVE` | 이번 달 사용량을 다 써서 저장하지 않았습니다. 고른 단어는 그대로 있습니다. {다음 달 1일}부터 저장할 수 있고, 더 필요하면 관리자에게 문의해 주세요. | 검토 화면 저장 |
| `LIMIT_REGEN` | 이번 달 사용량을 다 써서 뜻을 다시 만들지 못했습니다. 원래 뜻은 그대로입니다. {다음 달 1일}부터 다시 만들 수 있고, 더 필요하면 관리자에게 문의해 주세요. | 문서 화면의 여러 단어 다시 만들기, "모두 다시 시도" |
| `LIMIT_CARD` | 이번 달 사용량을 다 써서 뜻을 만들 수 없습니다. {다음 달 1일}부터 다시 만들 수 있고, 더 필요하면 관리자에게 문의해 주세요. | 복습 카드의 용례 아래 |
| `LIMIT_SLOT` | 이번 달 사용량을 다 썼습니다 · 관리자에게 문의해 주세요 | 문서 단어 목록의 행 버튼 자리(260px 열, 두 줄까지) |

- `lib/regen-messages.ts`에 같이 둔다.
- 화면은 **한도 결과를 다른 실패와 구별해서** 받아야 한다. 예: `{ error: "limit", resetsOn: "11월 1일" }`. 정확한 형태는 계획서에서 정한다.

## 3. 표시 부품

- **`Notice`(기본 tone = hard):** 화면 단위 안내 한 줄, 왼쪽 3px hard 줄 + surface 바탕. `role="alert"`
- **`Limited`(새 부품):** `Failed`와 같은 모양에 표시 줄만 바꾼다. 길이 10px, 두께 2px의 **실선**, 색 `hard`. 글자는 muted 13px(카드 안에서는 12.5px). 글이 여러 줄이 되면 표시 줄은 첫 줄에 맞춘다(`align-items: baseline`). `aria-live="polite"` 영역 안에 둔다

## 4. 나오는 곳

### 4.1 검토 화면 저장(`/documents/[id]/review`)

- 도구 줄(저장 버튼 줄) 바로 아래 `Notice`로 `LIMIT_SAVE`를 보인다. 지금 저장 오류가 나오는 자리(`px-10 pt-3`)다.
- 표는 그대로 둔다. 체크한 것, 해제한 것, 필터, 포커스 행을 모두 유지한다.
- 저장 버튼은 다시 누를 수 있게 둔다(관리자가 한도를 올렸을 수 있다). 다시 눌러 또 막히면 같은 안내가 그대로 남는다.
- 저장 버튼을 누르면 안내를 지운다. 성공하면 지금처럼 단어 목록으로 이동한다.

### 4.2 문서 화면 다시 만들기(`/documents/[id]`)

- **단어 하나(행의 "뜻 다시 만들기"):** 그 행의 버튼 자리에 `Limited` + `LIMIT_SLOT`을 둔다. 260px 열에서 두 줄로 접힌다. 뜻은 원래대로 진하게 되돌린다(흐림 해제). 다음 동작 전까지 남는다.
- **여러 단어, "모두 다시 시도":** 화면 위 안내 자리(지금 실패 안내 줄과 "모두 다시 시도"가 있는 곳)에 `Notice`로 `LIMIT_REGEN`을 둔다. 지금은 "모두 다시 시도" 결과를 `text-again` 글자로 보이는데, 한도 결과는 반드시 `Notice`로 보인다.
- 한도에 한 번 걸렸다고 다른 행의 버튼을 숨기지는 않는다. 누르면 같은 결과가 같은 자리에 나온다.

### 4.3 복습 카드의 다시 만들기(`/study`)

- 그 용례의 출처 줄 **아래 한 줄을 통째로** 써서 `Limited` + `LIMIT_CARD`를 보인다. PC에서 다시 만들기 버튼은 출처 줄 오른쪽 끝에 있지만, 한도 문구는 길어서 그 자리에 넣지 않는다. 휴대폰에서는 원래 버튼이 출처 아래 줄에 있으므로(7.4) 같은 자리다.
- 원래 뜻을 진하게 되돌린다. 1·2·3 응답과 다음 카드는 그대로 된다. 다음 카드로 넘어가면 문구가 사라진다(다른 다시 만들기 결과와 같은 규칙).

## 5. 관리 화면 사용량(`/admin`)

### 5.1 배치

- 폭을 **760px → 880px**로 넓힌다. 열이 하나 늘어나기 때문이다.
- 제목 "사용자"와 요약 줄 아래, 표 위에 **비용 칸**을 둔다. 아래 16px를 띄운다.
- 표에 **"이번 달 단어"** 열을 더한다. 순서: 사용자 / 상태 130px / 이번 달 단어 130px(오른쪽 정렬) / 가입 120px / 동작 150px(오른쪽 정렬). 가입·동작·숫자 칸은 줄바꿈하지 않는다.
- 표 아래 12.5px muted 한 줄: "한도: 사용자당 월 4,000단어 · 전체 월 $5.00"(환경변수 값을 그대로 보인다).

### 5.2 비용 칸

- surface 바탕, line 테두리, `radius-lg`, `shadow-1`, 안쪽 14px 18px. 가로 한 줄: [라벨/값] [막대] [비율]
- 라벨 "이번 달 Gemini 비용": 12px 600 muted
- 값 "$0.42": 20px 700 `tabular-nums`. 뒤에 " / $5.00"을 14px muted로 붙인다. 소수 둘째 자리까지 쓰고, $0.005 미만은 "$0.00"으로 쓴다(반올림).
- 막대: 4px 높이, 바탕 sunken, 채움 색은 비율에 따라 바뀐다. 선이므로 빨강·노랑을 써도 된다(개편안 7장).
  - 80% 미만: accent
  - 80% 이상: hard
  - 100%: again. 이때 비율 자리 문구는 "상한 도달 · 뜻 만들기 멈춤"
  - `role="meter"`에 `aria-valuenow`·`aria-valuemax`를 둔다.
- 비율: 12px muted, 정수 %
- 아래 줄 12.5px muted: "10월 1일부터 · 한국 시간. 매월 1일 0시에 새로 셉니다. 정산 중인 요청은 예상 비용으로 셉니다."
- 값은 맡아 둔(정산 전) 예상 비용을 포함한다. 한도 계산과 같은 값을 보여 줘야 "아직 $4.9인데 왜 막혔나" 같은 혼란이 없다.

### 5.3 "이번 달 단어" 칸

- 숫자 14px `tabular-nums`, 천 단위 쉼표, 단위는 붙이지 않는다(열 이름에 "단어"가 있다). 0은 muted로 쓴다.
- 한도에 닿았으면(합 ≥ 한도) 숫자 앞에 hard 점, 뒤에 "한도"를 붙인다. 예: "● 4,000 한도". `Status` 모양이다.
- 다른 상태 표시나 경고는 두지 않는다.

# 2부. C-3 휴대폰 복습 화면

## 6. 원칙

1. **엄지가 닿는 아래쪽에 답 버튼을 둔다.** 지하철에서 한 손으로 쥐고 엄지로 누른다. 화면 위쪽은 읽는 곳, 아래 고정 줄은 누르는 곳이다.
2. **PC 화면은 바꾸지 않는다.** 휴대폰 배치는 폭 640px 미만에서만 쓴다. 키보드 단축키는 폭과 상관없이 늘 동작한다.
3. **터치 기기에서는 단축키 표시(`Kbd`, "[P] 발음 듣기")를 숨긴다.** 기준은 폭이 아니라 `@media (hover: none) and (pointer: coarse)`다. 좁은 창의 PC에서는 단축키 표시가 그대로 보인다.
4. **누르는 범위는 44px 이상.** 글자 버튼(점선 밑줄)은 모양은 그대로 두고, 가상 요소로 누르는 범위만 넓힌다.

## 7. 휴대폰 배치(폭 640px 미만)

### 7.1 전체

```
┌ 상단 바 52px ─────────────────────┐
│ 진행 줄                           │ 화면과 함께 스크롤
│ ┌ 카드 ─────────────────────────┐ │
│ │ …                             │ │
│ └───────────────────────────────┘ │
├ 고정 줄(sticky bottom) ───────────┤ 항상 보임
│   되돌리기 · 상태 줄 (32px)        │
│ [ 모름 ][ 애매 ][ 앎 ]  또는 [뒷면 보기] │
└ safe-area 여백 ───────────────────┘
```

- 페이지는 일반 스크롤(문서 스크롤)이다. 카드 안에 따로 스크롤을 두지 않는다. iOS에서 안쪽 스크롤은 끝에서 바깥이 따라 움직이고 관성도 어색하다.
- 고정 줄은 `position: sticky; bottom: 0`이다. 바탕 `bg`(페이지 바탕), 위에 1px line, 안쪽 8px 16px, 아래쪽은 `calc(12px + env(safe-area-inset-bottom))`. `<meta name="viewport">`에 `viewport-fit=cover`가 있어야 safe-area 값이 들어온다.
- 좌우 여백 16px. 페이지 래퍼의 위 여백은 0이고 진행 줄이 14px를 가진다.
- 높이는 `100dvh`를 기준으로 잡는다(주소창이 접히고 펴져도 고정 줄이 가려지지 않게). `vh`는 쓰지 않는다.

### 7.2 상단 바(모든 화면 공통, 640px 미만)

- 작업명 "slave-voca"를 숨긴다. 왼쪽 여백 24px → 12px, 메뉴 안쪽 여백 12px → 10px.
- 계정 버튼은 머리글자 원만 둔다(M6-1 5.2에서 정함). 관리자의 "관리 n"은 그대로 둔다.
- 360px에서 "홈 · 복습 n · 문서 · 관리 n · 설정 · (원)"이 한 줄에 들어가야 한다. 넘치면 메뉴 사이 간격(gap 2px)부터 줄인다.

### 7.3 진행 줄

- "3 / 22 ▬▬▬ 남은 19", 13px muted. 지금과 같은 모양이고 위 14px, 좌우 16px다.

### 7.4 카드

- 바깥 여백 위 12px, 좌우 16px. 안쪽 22px 20px 20px. 모서리·그림자는 PC와 같다.
- **단어:** 앞면 36px, 뒷면 30px. en 700, 줄높이 1.1.
  - 13자 이상인 단어는 한 단계 작게 쓴다(앞 28px, 뒤 24px).
  - 그래도 넘치면 `overflow-wrap: anywhere`로 줄을 바꾼다. 가로로 넘치는 일은 없어야 한다.
  - 예: "heteroscedasticity"(18자)는 360px 폭에서 24px로 한 줄에 들어간다.
- **발음 버튼:** 40px 원. 가상 요소로 누르는 범위를 48px로 넓힌다. 단어 오른쪽 10px. 단어가 두 줄이 되어도 원은 첫 줄 높이에 둔다(`align-self: flex-start` + 위치 보정).
- **"새 카드" 배지:** 지금과 같다.
- **앞면:** 카드가 고정 줄 위까지 남은 높이를 모두 채운다(누르는 범위를 넓히려고). 아래쪽 가운데 문구 두 줄:
  - "이 문서에서 어떤 뜻이었는지 떠올려 보세요"(14px muted)
  - "카드를 누르거나 아래 버튼"(12.5px muted)
- **뒷면(위에서부터):**
  1. 단어 + 발음 버튼
  2. 발음기호(en 17px muted). 없으면 "발음기호 없음"(15px muted)
  3. 첫 용례: 위 구분선(line) 16px 뒤에 문맥 뜻(sans 20/1.45 700), 원문(en 16.5/1.6 ink-2, 형광펜), 출처("— " + en 13.5px 기울임 muted)
  4. 출처 아래 줄에 다시 만들기 자리(13px). PC처럼 출처 줄 오른쪽 끝에 두지 않는다. 출처 제목이 길어 두 줄이 되면 버튼이 이리저리 옮겨 다니기 때문이다.
  5. 둘째 용례: 점선 구분선, 뜻 16px 700, 원문 15px. 나머지는 첫 용례와 같다.
- 용례는 지금처럼 최대 둘이다.

### 7.5 뒷면 열기

- 앞면에서는 **카드 어디를 눌러도** 뒷면이 열린다. 고정 줄의 "뒷면 보기" 버튼도 같은 동작이다.
  - 카드 안의 발음 버튼은 뒷면을 열지 않는다(`stopPropagation`).
  - 카드는 `role="button"`이 아니라 클릭만 받는다. 키보드와 읽기 프로그램 사용자에게는 "뒷면 보기" 버튼이 있다. 중복 탭 정지를 피하려는 것이다.
- 뒷면에서는 카드를 눌러도 아무 일이 없다. 잘못 눌러 화면이 바뀌는 일을 막는다.
- 뒷면을 열면 스크롤을 카드 맨 위로 맞춘다(뒷면이 길어 아래로 내려가 있던 경우).
- 뒤집는 애니메이션은 넣지 않는다(개편안 3.4).

### 7.6 고정 줄

- **위 줄(32px 고정 높이, 가운데 정렬, 13px muted, `aria-live="polite"`):** 아래 중 하나가 들어간다. 비어 있어도 높이는 그대로라서 아래 버튼 위치가 변하지 않는다.

  | 상태 | 내용 |
  |---|---|
  | 되돌릴 응답 있음 | [되돌리기](점선 밑줄 버튼) `latent`(en ink-2) · 앎(응답 색) |
  | 되돌린 뒤 | `latent` 응답을 되돌렸습니다 |
  | 되돌리기 거부 / 실패 | PC와 같은 문구. 실패면 "· 다시 시도" 버튼을 붙인다 |
  | 저장 중(누른 뒤 400ms가 지나도 끝나지 않을 때) | 회전 고리 + "저장 중" |
  | 저장 실패 | `Failed` "응답을 저장하지 못했습니다 · 다시 눌러 주세요"(`role="alert"`) |

  - 우선순위: 저장 실패 > 저장 중 > 되돌리기 결과 > 되돌릴 응답.
  - 저장 중을 400ms 뒤에 보이는 이유: 빠른 망에서 깜박이지 않게 하려는 것이다. 휴대폰 망은 느릴 때가 있어, 아무 표시 없이 버튼만 흐리면 눌렸는지 알 수 없다.
  - 저장 실패 문구는 서버 오류 문구 대신 이 고정 문구를 쓴다. 지금 PC는 서버 문구를 `text-again` 글자로 보이는데, PC도 같은 `Failed` 문구로 바꾼다(빨강은 점과 선에만).

- **아래 줄:**
  - 앞면: "뒷면 보기" 버튼. 폭 전체, 높이 52px, surface, line-strong 테두리, `radius-lg`, 16px 600. 단축키 표시는 숨긴다(터치 기기).
  - 뒷면: 답 버튼 셋. 3열, 사이 8px, 높이 60px, `radius-lg`. 응답 이름 16px 700, 그 아래 "1분 뒤" 12px opacity .8. 색은 지금 PC와 같은 옅은 바탕 + 진한 글자다. 단축키 표시는 숨긴다.
  - 저장 중에는 답 버튼 셋 모두 `disabled`(opacity .55)다. 지금 PC와 같다.
- 누를 때 반응: 버튼마다 `:active`에서 바탕을 한 단계 진하게 한다(`color-mix(in srgb, currentColor 10%, 바탕)`). iOS 기본 탭 강조는 끈다(`-webkit-tap-highlight-color: transparent`).
- 두 번 탭 확대를 막으려고 버튼과 카드에 `touch-action: manipulation`을 둔다.
- 답 버튼을 빠르게 두 번 누르면 두 번째는 무시한다. 지금 `locked` ref가 이미 막고 있다.

### 7.8 발음

- 발음 버튼을 누르면 읽는다. 지금과 같다.
- **자동 발음:** 뒷면을 여는 탭(카드 또는 "뒷면 보기")의 클릭 처리 안에서 바로 `speak()`를 부른다. iOS는 사용자 동작 안에서 시작한 음성만 허용하므로, effect나 setTimeout으로 미루면 막힌다. 지금 `reveal()`이 이미 그렇게 한다. 휴대폰 배치에서도 이 경로를 바꾸지 않는다.
- 그래도 소리가 나지 않으면(무음 모드, 브라우저 제약) 화면에 따로 알리지 않는다. 발음 버튼으로 언제든 다시 들을 수 있다.
- 음성 합성을 지원하지 않으면 발음 버튼을 숨긴다(지금과 같음).

## 9. 나머지 화면: 폭 360px에서 가로 스크롤 없게

다듬지는 않고 깨지지 않게만 한다. 공통 규칙은 다음과 같다.

| 규칙 | 내용 |
|---|---|
| 페이지 여백 | 640px 미만에서 좌우 16px(지금 40px인 표 화면 포함) |
| 표 | **페이지가 아니라 표를 감싼 상자가** 가로로 스크롤한다(`overflow-x: auto`). 페이지 자체(`document.documentElement.scrollWidth`)는 화면 폭을 넘지 않는다. 문서 목록, 문서 단어 목록, 검토 후보 표, 관리 사용자 표가 해당한다 |
| 2열 배치 | 1열로 쌓는다. 홈의 두 패널, 설정의 라벨/입력(라벨이 위로) |
| 도구 줄 | `flex-wrap`으로 접는다. 검토 화면 도구 줄의 필터 칩·저장 버튼, 문서 화면 안내 줄 |
| 긴 영어 | 문서 제목과 원문 문장에 `overflow-wrap: anywhere` |
| 버튼과 입력 | 입력칸 글자는 16px 이상(iOS가 포커스할 때 확대하지 않게). 설정의 숫자 칸, 업로드 |
| 상단 바 | 7.2 |

- 검토 화면은 J/K·Space·Ctrl+Enter로 쓰는 PC 화면이다. 휴대폰에서는 체크박스를 누르고 저장 버튼을 누를 수 있으면 된다.
- 로그인·승인 대기·사용 중지 화면은 M6-1에서 이미 맞췄다.

## 10. 확인 기준(검수 때 볼 것)

헤드리스 브라우저를 360×740, 390×844로 띄운다. 터치 에뮬레이션(`hasTouch`, `isMobile`)을 켜서 `pointer: coarse`가 되게 한다.

- 복습 앞면·뒷면·저장 중·저장 실패·되돌린 뒤·다시 만들기 진행 중·한도·끝·빈 화면 두 종류를 360·390 두 폭에서 본다. 라이트·다크 모두 본다.
- 고정 줄이 늘 화면 아래에 보이는지, 뒷면이 길 때 스크롤해도 답 버튼이 가려지지 않는지 본다.
- 18자 단어("heteroscedasticity")가 360px에서 넘치지 않는지 본다.
- 터치 에뮬레이션에서 `Kbd`가 보이지 않고, 터치를 끈 좁은 창에서는 보이는지 본다.
- 카드 탭으로 뒷면이 열리고, 발음 버튼 탭으로는 열리지 않는지 본다.
- 나머지 화면 9개(홈, 로그인, 승인 대기, 사용 중지, 설정, 문서 목록, 문서 상세, 관리, 검토)를 360px에서 열어 `scrollWidth`가 360 이하인지 잰다.
- C-1: 한도를 작게 둔 환경에서 세 곳의 안내 문구, `Limited` 표시 줄 색(hard 실선), 관리 화면 비용 칸의 세 단계 색을 본다.
